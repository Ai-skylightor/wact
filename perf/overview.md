# 性能测试总览

性能测试是平台的独立模块（与接口测试、UI 测试平级），从门户首页「⚡ 性能测试」卡片进入。当前对接**换电柜扫码换电月度并发压测**：500 并发、两阶段（主用例 + 异常场景）各 60 分钟，由内网压测工程执行，平台负责触发、进度展示、报告与逐月趋势。

## 架构与调用链

```
浏览器 → 平台前端（perf_index.html）
              │  仅调平台自己的接口
              ▼
         平台后端 /api/monthly-perf/*（后端代理，注入 X-Monthly-Token）
              │  VPN 内网转发
              ▼
         压测工程 192.168.0.113:5050（/monthly/run|status|report|trend|stop）
              │
              ▼
         被测环境 192.168.0.112（EMQX / MySQL / Kafka / Redis）
```

- 浏览器**不直连**内网压测工程，压测地址与 token 永不出现在前端代码中；
- 平台代理接口有角色控制：触发/停止需 **editor** 及以上，查看进度/报告/趋势仅需 **viewer**；
- 触发人由平台操作日志自动记录。

## 页面功能

| 区域 | 说明 |
|------|------|
| 执行总览 | 服务状态灯、立即执行 / 停止按钮、9 步流水线步进器（每 5 秒轮询，完成 ✓ / 当前脉冲 / 失败 ✕）、失败原因自动翻译、关键指标卡片（取本空间最新归档） |
| 测试报告 | **本空间**报告归档列表（已归档 / 待归档、手动 / 定时触发），点击查看完整 Markdown 报告 |
| 定时任务 | 创建月度定时任务（HTTP 触发型），执行结果自动推企业微信群 |
| 趋势追踪 | 逐月 TPS / 成功率双轴折线 + 明细表（从**本空间**归档聚合） |
| 使用说明 | 架构、周期、手动执行、注意事项 |

**空间隔离**：报告、趋势与关键指标均按空间归档隔离——平台触发的每轮执行先在当前空间写占位记录，报告从压测引擎拉取后回填到该空间（`monthly_perf_reports` 表带 `space_id`，配合平台空间自动过滤）。每个空间只能看到自己触发的压测记录，一个空间不影响另一个空间。压测引擎为全局单实例：同一时刻只能跑一轮（运行中重复触发返回 409），执行状态展示的是引擎当前任务。

进度语义（对接契约）：

- `total_steps` 恒为 9；`step_index` 存在 7→8 跳变，前端直接使用返回的 `step` 文本渲染；
- 终态 = `running == false && return_code != null`，`return_code == 0` 为成功；
- 执行中重复触发返回 409，可选择「停止后重试」或「强制覆盖」（force）。

## 定时执行（CI 任务）

月度自动化通过 **CI/CD 定时任务**的「HTTP 触发型」实现。推荐直接在性能测试模块的 **⏰ 定时任务** 页签创建：填任务名 → 点「每月第一个周日 02:00」预设按钮 → 勾选失败/成功是否通知 → 创建。触发 URL 与请求体由平台自动填写（地址来自后端配置，不进前端）。执行结果自动推送**企业微信群**（与 AI 用例评审共用同一个群机器人，即 system_config 的 `wechat_review_webhook`；未配置群 webhook 时跳过通知）。任务也可在 接口自动化 → CI/CD 定时任务 中统一管理（列表带「HTTP 触发」徽章）。

等效的手动配置参数：

| 配置项 | 值 |
|--------|-----|
| 任务类型 | 🌐 HTTP 触发外部系统 |
| Cron | `0 2 1-7 * *`（每月 1-7 日每天 02:00 触发，周日判定由压测侧脚本完成） |
| 触发 URL | `http://192.168.0.113:5050/monthly/run` |
| 请求体 | `{"weekday_check": true}`（默认已预填，勿删） |

::: warning 为什么必须带 weekday_check
压测侧 `/monthly/run` 默认以 `--force-weekday` 启动（为了让手动「立即执行」任意日期可用）。若定时任务不带 `weekday_check: true`，会在每月 1-7 号**每天**凌晨全量跑一轮 5.5 小时压测并两次清空被测环境库。带上后，非周日触发时编排脚本秒级静默退出（CI 显示成功属正常现象）。
:::

cron 也不能写成 `0 2 1-7 * 1`：day-of-week 的 `1` 是周一而非周日，且与 day-of-month 同时受限时 cron 按 OR 语义（1-7 号 ∪ 每个周一都触发）。

## 平台侧配置（按空间角色，一次性）

代理地址与认证 token 推荐**在页面上配置**（未配置 token 时除探活外会返回明确提示）：

**方式一：页面配置（推荐）** —— 进入 性能测试 → 执行总览 → **⚙️ 对接配置**（查看需空间 viewer 及以上，保存/清除需 **editor** 及以上，与「立即执行」同级），填入 token 保存即可。配置存 `system_config` 表：**即时生效、无需重启后端**，随数据库走，**发版 / 换服务器部署不丢**（此前文件方式因 `.gitignore` 排除密钥，git 发布不会带上，线上需重新配置——页面方式彻底解决了这个问题）。面板同时回显当前生效来源与 token 掩码；提供「清除页面配置」回落到环境变量 / 配置文件。

**方式二：配置文件**（页面方式之前的旧方式，保留作兜底）—— 复制 `backend/monthly_perf_config.example.json` 为 `backend/monthly_perf_config.json`，填入真实 token 后重启后端。真实配置文件已被 `.gitignore` 排除，密钥不会入库。

**方式三：环境变量**（优先级最高，运维兜底；设置了则以它为准，页面保存不生效）：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `MONTHLY_PERF_BASE_URL` | `http://192.168.0.113:5050` | 压测工程地址 |
| `MONTHLY_PERF_TOKEN` | （空） | 压测侧 `config/monthly_api_config.json` 的 `api.auth_token` |

Windows 启动示例：`set MONTHLY_PERF_TOKEN=monthly-perf-xxxxxx && python app.py`（注意 `set` 只对当前 cmd 窗口生效，须在启动后端的同一窗口执行）；Linux：`export MONTHLY_PERF_TOKEN=...`。

优先级汇总：**环境变量 > 页面配置（system_config）> 配置文件 > 默认地址**。每次请求动态解析，任何一处修改保存后立即生效。

## 注意事项

1. **手动执行会两次清空并重造被测环境数据**，全程约 5.5 小时（含两次清空 + 造数据各约 40 分钟）；
2. 环境冻结窗口：触发前 30 分钟至报告产出，期间禁止部署被测环境，否则趋势不可比；
3. 平台到压测工程的 **VPN 为硬依赖**，断链时所有接口显示「不可达」；
4. 停止已在压测侧修复为**整进程组终止**（SIGTERM → 5 秒宽限 → SIGKILL 兜底）：按下停止后编排进程与压测孙进程会被一并终止，不再出现「假成功」；进程退出仍可能需要数秒，以进度状态为准；
5. 报告中的「不一致详情表」可能包含测试账号手机号，仅限内部使用；
6. 压测侧 Linux cron 兜底与平台 CI 并存，若同时触发，后触发方会收到 409，属预期。
