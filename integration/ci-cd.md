# CI/CD 定时任务

CI/CD 定时任务是平台内置的**调度器**（基于 APScheduler），让接口测试套件按 cron 表达式自动执行。常用于"每天凌晨跑一次回归""每小时巡检一次核心接口"这类周期性测试场景，不依赖外部 CI 工具。

![CI/CD 定时任务](/screenshots/zh/ci_tasks.png)

::: tip 定时任务 vs Jenkins 触发
- **定时任务（本页）**：平台自己按时间触发，适合**周期性回归**
- **Jenkins 触发**：Jenkins 发版后主动调用平台 API 触发，适合**发版即测**

两者不冲突，可以同时用：日常每天定时跑全量，发版时 Jenkins 触发关键套件。
:::

## 功能定位

| 能力 | 说明 |
|------|------|
| **Cron 调度** | 标准 5 / 6 段 cron 表达式，精确到分钟 |
| **关联套件** | 一个定时任务对应一个测试套件 |
| **手动触发** | 不等定时，立即跑一次 |
| **启停控制** | 临时停用，不删除任务 |
| **多渠道通知** | 企业微信 / QQ 机器人 / 邮箱，可选失败通知或全部通知 |
| **执行身份** | 选择用哪个用户的全局参数和 Token 执行 |

## 创建定时任务

### 步骤

1. 进入 **AI 功能 → CI/CD 定时任务**，点「+ 新建任务」
2. 填写以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| **任务名称** | 唯一标识 | `每日凌晨回归` |
| **关联测试套件** | 选择已创建的测试套件 | `核心接口回归` |
| **Cron 表达式** | 调度规则（5 段：分 时 日 月 周） | `0 2 * * *` |
| **通知方式** | 不通知 / 企业微信 / QQ 机器人 / 邮箱 | `企业微信` |
| **通知地址** | Webhook URL 或邮箱 | `https://qyapi.weixin.qq.com/...` |
| **通知条件** | 仅失败通知 / 全部通知 | `仅失败通知` |
| **执行身份** | 用哪个用户的参数和 Token 跑 | `默认（任务创建者）` |

3. 点「保存」，任务默认启用，下一次到达 cron 时间点时自动执行

### Cron 表达式速查

Cron 表达式由 5 段组成：`分 时 日 月 周`，每段用空格分隔。

| 表达式 | 含义 |
|--------|------|
| `0 2 * * *` | 每天凌晨 2:00 |
| `0 8,20 * * *` | 每天 8:00 和 20:00 各一次 |
| `*/30 * * * *` | 每 30 分钟一次 |
| `0 0 * * 1` | 每周一 0:00 |
| `0 0 1 * *` | 每月 1 号 0:00 |
| `0 9-18 * * 1-5` | 工作日 9:00-18:00 每小时（朝九晚六巡检） |

::: warning 时区
Cron 时间按**服务器本地时区**计算，不是浏览器时区。如果服务器在 UTC、你在 UTC+8，记得换算时差。建议先在服务器上跑 `date` 确认时区。
:::

## 启停与手动执行

每个任务行右侧有三个常用操作：

| 操作 | 说明 |
|------|------|
| **启用 / 禁用** | 临时停用，保留配置不删除 |
| **立即执行** | 不等 cron 时间，立即触发一次（同样走通知逻辑） |
| **编辑 / 删除** | 修改配置或彻底删除 |

::: tip 立即执行用于验证通知配置
新建任务后建议先点一次「立即执行」，验证：

1. 测试套件本身能否跑通
2. 通知渠道（企业微信 Webhook 等）是否真的能收到消息
3. 通知条件（仅失败 / 全部）是否符合预期

避免配置错误等到第二天才发现通知一直没发出去。
:::

## 执行身份选择

「执行身份」字段决定 CI 跑测试时**用哪个用户的全局参数和 Token** 发请求，这直接影响：

- 请求头里的 `Authorization`（来自该用户的全局参数）
- baseUrl 的默认值（来自该用户的全局参数）
- 报告归属（默认归属执行身份）

### 何时需要切换执行身份

| 场景 | 推荐配置 |
|------|---------|
| **单团队**（所有人共享同一份参数） | 用任务创建者即可 |
| **多环境**（不同用户配置不同 baseUrl） | 选对应环境的用户 |
| **专用 CI 账号**（推荐做法） | 建一个名为 `ci-bot` 的用户，专门存 CI 用的 Token 和参数 |
| **权限隔离**（不同业务线分开） | 每个业务线一个 CI 账号 |

::: warning 选错执行身份 = 测试全挂
最常见的 CI 事故：执行身份选了 A 用户，但 A 用户的全局参数里 `baseUrl` 还指向旧环境 / Token 过期了，结果整批用例 401 / 连接超时。

排查时：到「全局参数」页切换到对应执行身份的视图，看 baseUrl 和 Token 是否有效。
:::

## 通知配置

### 企业微信机器人

1. 在企业微信群内添加机器人，获取 Webhook URL（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`）
2. 把 URL 填入"通知地址"
3. 平台在通知时会推送卡片消息，包含：

- 任务名称
- 通过 / 失败用例数
- 失败用例摘要（前 5 条）
- 报告详情链接

### QQ 机器人

填 QQ 机器人的接收 URL，平台同样推送结构化消息。

### 邮箱

填收件邮箱地址，平台用配置好的 SMTP 服务发邮件。SMTP 配置由运维在后端配置文件设置。

## 任务列表与历史

任务列表只展示**当前活跃的定时任务**，不展示执行历史。要看历次执行结果，去 **执行与结果 → 测试报告**，按时间倒序查看，定时任务触发的执行记录会标注来源。

## 与回归测试集的分工

| 维度 | CI/CD 定时任务 | CI 回归测试集 |
|------|---------------|---------------|
| 触发方式 | 平台自己按 cron 时间触发 | Jenkins / 外部 API 调用触发 |
| 关联内容 | 单个测试套件 | 多个套件 + UI 工作流的组合 |
| 适用场景 | 周期性回归、巡检 | 发版即测、按环境匹配 |
| 是否阻塞流水线 | 不阻塞（异步） | 可阻塞（同步返回 finalStatus） |

两者常配合使用：定时任务做日常巡检，回归测试集做发版把关。回归测试集详见 [CI 回归测试集](./regression.md)。

## 常见问题

::: warning 定时任务没按时执行？
排查清单：

1. 任务是否处于「启用」状态（被禁用的不执行）
2. Cron 表达式是否正确（特别注意空格、星号位置）
3. 服务器时区是否和预期一致
4. 关联的测试套件是否还有用例（套件被清空后任务跑空）
5. 后端调度器进程是否在运行（联系运维查日志）
:::

::: tip 一个测试套件能挂多个定时任务吗？
可以。同一个套件可以被多个定时任务引用，例如：

- `0 2 * * *` 每天凌晨跑一次全量
- `*/30 * * * *` 每 30 分钟跑一次（同套件，但通知条件可以设成"仅失败"做实时告警）

只要任务名称不重复即可。
:::
