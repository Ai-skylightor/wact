# UI 测试平台总览

UI 测试平台是五号智能云测试平台面向 **Web 端** 的可视化测试解决方案。测试人员通过**拖拽步骤 + 元素拾取 + AI 辅助生成**的方式编排测试流程，由 Playwright 驱动浏览器自动执行，并产出每步截图、视频回放与可导出的测试报告。

与平台已有的接口测试模块相比，UI 测试面向的是用户真实操作路径（点击、填写、断言页面表现），目标是替代"点点点"的人工回归。本节先给出平台能力全景，帮助你在动手前建立整体认知。

![UI 测试平台仪表盘](/screenshots/zh/ui_dashboard.png)

## 七个核心模块

平台左侧导航共 7 个模块，分别覆盖编排、管理、执行、复用、审计五类工作场景：

| 模块 | 作用 | 典型频率 |
|------|------|---------|
| **总览** | 流程总数、执行次数、通过率，快速开始引导 | 低（看数据） |
| **流程编排** | 创建项目/模块、编排并执行测试流程（核心工作区），支持批量执行 | 高 |
| **元素库** | 项目/模块/页面三级，录制拾取与管理页面元素 | 高 |
| **执行记录** | 历次执行列表，查看详情（含视频回放）、终止任务、导出报告 | 高 |
| **模板库** | 所有可用模板（含参数说明），编写前查阅 | 低（参考） |
| **操作日志** | 增删改查、执行、导出等操作的审计记录 | 低（审计） |
| **定时任务** | 配置 Cron 定时执行流程，无人值守回归 + 结果通知 | 中（回归期） |

::: tip 推荐的使用顺序
一个完整的 UI 测试任务，建议按以下流程推进：**准备项目结构 → 录制元素库 → 编排流程 → 调试执行 → 正式执行 → 查看报告 → 维护**。先建元素库、再编排流程，可以让元素被多流程复用、改一处全流程生效。
:::

## 与接口测试平台的区别

UI 测试平台与平台内的接口测试模块共用同一套用户体系与权限隔离，但定位完全不同：

| 维度 | 接口测试平台 | UI 测试平台 |
|------|-------------|------------|
| 测试对象 | 后端 API（HTTP 请求/响应） | 浏览器中渲染的页面与交互 |
| 编排单位 | 接口调用 + 参数 + 断言 | 页面操作步骤（点击、填写、等待、断言） |
| 执行驱动 | HTTP 客户端 | Playwright 浏览器自动化 |
| 结果证据 | 响应体、状态码、耗时 | 每步截图、视频回放、HTML/MD 报告 |
| 适用场景 | 接口契约、数据校验、性能基线 | Web 回归测试、功能验证、UI 稳定性 |

简而言之，接口测试关心"后端对不对"，UI 测试关心"用户能不能正确完成操作"。两者互补，共同覆盖一个被测系统的全链路质量。

## data-testid 定位理念

UI 自动化最大的维护成本来自**元素定位失效**——前端改版后，写死的 CSS / XPath 选择器往往会大面积失效。本平台在定位策略上坚持以下原则：

1. **优先 `data-testid`**。10 种内置定位策略中（`data-id` / `row-id` / `text` / `role-text` / `row-action` / `placeholder` / `label` / `role` / `css` / `xpath`），`data-testid` 不受多语言切换、文案改动、样式重构影响，是稳定性最高的策略。
2. **主策略 + 兜底策略降级**。每个步骤都允许配置兜底定位，主策略失败时自动降级，兼顾稳定与兼容。
3. **元素集中管理 + 引用追踪**。元素统一在元素库维护，平台自动追踪每个元素被哪些流程的哪一步引用，删除有引用保护，改一处即可评估全局影响。

::: warning 多语言系统的注意事项
被测系统若支持多语言，拾取元素时务必优先选择 `data-testid` / `id` / `name` 等语言无关策略，避免把文案或 placeholder 作为主策略，否则切换语言即大面积失效。
:::

## 适用场景

UI 测试平台尤其适合以下场景：

- **Web 回归测试**：每次发版前批量执行核心流程，确认已有功能未被破坏。
- **功能验证测试**：新功能上线前对关键操作路径（登录、查询、新增、编辑、删除）做端到端验证。
- **多浏览器兼容**：通过 chromium / firefox / webkit 三种浏览器引擎切换，验证页面表现一致性。
- **无人值守回归**：配合定时任务模块，用 Cron 表达式调度夜间回归，结果通知到企业微信/QQ 机器人/邮件。
- **复杂业务流程**：借助条件分支、循环、变量传递能力，编排贴近真实业务逻辑的测试（如分页遍历、弹窗二次确认）。
