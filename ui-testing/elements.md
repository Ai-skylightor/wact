# 元素库

元素库是 UI 测试平台对抗"定位失效"与"维护成本爆炸"的核心模块。它把页面元素从流程步骤里抽离出来集中管理，让一个元素的定位修改能被所有引用它的流程感知，并提供录制拾取、健康检查、引用追踪三重保障。

元素库**独立于**流程编排，有自己的一套项目 / 模块 / 页面层级。建议在编排流程**之前**先建好元素库，这样在配置步骤时可以直接从元素库选择，让定位策略、定位值与兜底策略自动回填。

## 项目 → 模块 → 页面 → 元素分层

元素库采用四级层级，与被测系统的真实结构对齐：

```
项目（对齐被测系统，如 ARC RIDE 管理平台）
  └─ 模块（对齐业务菜单，如 门店管理、用户管理）
       └─ 页面（对齐具体操作页，如 门店列表页）
            └─ 元素（页面上的可交互元素，如 门店名称输入框）
```

**创建层级的步骤**：

1. 进入 **元素库** → 左侧 **[+ 项目]** → 输入项目名称
2. 展开项目 → 点击 **[+]** 添加模块
3. 选中模块 → **新建页面**，填写：页面名称（如 `门店列表页`）、页面 URL（如 `http://x.x.x.x/#/shopList`）
4. 选中页面 → 通过录制拾取或手动添加元素

::: tip 页面 URL 是入口
页面 URL 是**元素健康检查**与**录制拾取**的入口，务必准确。如果 URL 填错，录制时浏览器无法打开正确页面，健康检查也会全部失败。
:::

## data-testid 定位策略

每个元素在入库时都会记录一个定位策略 + 定位值，平台支持的 7 种策略按稳定性从高到低排序：

| 策略 | 稳定性 | 适用场景 |
|------|:---:|------|
| `data-id` (data-testid) | ★★★★★ | 推荐策略，不受多语言、文案、样式影响 |
| `id` | ★★★★ | 系统唯一 ID，适合内部管理系统 |
| `name` | ★★★★ | 表单字段常用 |
| `role` | ★★★ | ARIA 语义角色（button / textbox 等） |
| `label` | ★★★ | 表单控件的关联 label 文本 |
| `placeholder` | ★★ | 输入框占位文本，多语言下易失效 |
| `text` / `css` / `xpath` | ★ | 文案或结构依赖，最易失效 |

::: warning 多语言系统必看
被测系统若支持多语言切换，拾取时**必须优先选择 `data-testid` / `id` / `name` 等语言无关策略**。把文案或 placeholder 作为主策略会导致切语言后大面积失效。
:::

每个元素允许配置**主策略 + 兜底策略**。执行时主策略失败会自动降级到兜底，兼顾稳定与兼容。

## 元素录制器（Picker）

录制拾取是元素入库的推荐方式——相比临时手填选择器，它生成的定位值更准确，且天然纳入集中管理。

### 录制步骤

1. 在元素库选中目标**页面** → 点击 **[录制拾取]**
2. 在弹窗中配置：
   - **页面 URL**：自动带入，可修改
   - **需要先登录？** 点击展开，填写登录页 URL、账号、密码、（可选）租户域名
3. 点击 **[开始录制]** → 后台打开浏览器窗口并注入高亮脚本
4. 在浏览器中**悬停**目标元素（会高亮）→ **点击**采集，元素进入已采集列表
5. 可对已采集元素**重命名**或**删除**误采项
6. 采集完成 → 点击 **[完成并入库]** → 元素批量写入当前页面

### 自动命名规则

系统拾取时会按「类型[文本]」格式自动命名，无需手动起名：

- 带文案的元素：`按钮[查询]`、`输入框[手机号]`、`下拉框[语言切换]`、`下拉选项[中文]`、`链接[用户列表]`
- 无文案元素：仅用类型名，如 `密码框`、`图标`
- 同一批次内重名自动加序号：`按钮[确认]`、`按钮[确认](2)`

入库后建议重命名成更贴合业务的名称（如把 `下拉框[语言切换]` 改成 `顶部-语言下拉框`），便于跨流程检索。

### 扫描拾取（批量导入）

除了逐个点击采集，元素库还提供 **[扫描]** 按钮：一次性返回页面截图 + 所有可交互元素列表 → 勾选入库。适合新页面首次接入时快速批量导入。

::: tip 录制与扫描的区别
录制拾取适合**精准挑选**特定元素，定位策略可控；扫描拾取适合**快速批量**导入整页元素，但策略由系统自动判断，导入后建议人工抽查。
:::

## 元素健康检查

被测系统改版后，原先的定位可能集体失效。**健康检查**能在改版后快速发现哪些元素失效了：

- 进入页面详情页 → 点击 **[健康检查]**
- 后台用 Playwright 打开页面 URL，**逐个校验**每个元素当前能否被定位
- 返回结果按"通过 / 失败"分组展示，失败元素会显示具体原因（找不到 / 多匹配 / 超时）

建议在每次被测系统发版后，对所有核心页面跑一次健康检查，提前发现需要更新的定位，避免回归测试时才发现大面积失败。

## 引用追踪：影响面可见

元素库列表里，每个元素都会显示**被多少个流程步骤引用**（徽标数字）。引用关系是**自动建立**的——只要流程步骤的定位命中了该元素（无论是从元素库选的，还是手填的定位值一致），都算引用。

**关键能力**：

- 点击引用数 → 查看具体被哪些流程的哪一步引用
- **删除保护**：被引用的元素无法直接删除，需先移除流程中的引用（删除时会提示引用位置）
- **修改感知**：改一个元素的定位，能立刻知道影响哪些流程

::: tip 价值
没有引用追踪之前，改元素定位常常"改了不知道、忘了改的炸了"。引用追踪让每一次定位修改的影响面可见、可控，是降低维护成本的关键。
:::

## Page Object 模式

元素库的"项目 → 模块 → 页面 → 元素"分层，本质上就是 **Page Object 模式**的可视化实现：

- **页面 = Page Object**：每个页面对应一组元素的容器，封装了"这个页面上有哪些可操作元素"
- **元素 = Page Object 的字段**：定位策略与值集中维护，不散落在各个测试脚本里
- **流程 = 调用 Page Object 的方法序列**：流程步骤通过引用元素来操作页面，元素改了流程自动跟随

这种模式的好处是：**页面改版时只需在元素库更新一次定位，所有引用该页面的流程自动受益**。相比把选择器散落在各个测试脚本里，维护成本呈数量级下降。

## 元素维护最佳实践

1. **优先用 `data-testid`**：说服前端在关键元素上添加 `data-testid` 属性，是降低维护成本最有效的投入
2. **业务语义命名**：用 `顶部-语言下拉框` 而非 `下拉框[语言切换]`，让其他测试人员一眼能找到
3. **定期健康检查**：每次被测系统发版后跑一次健康检查，提前发现失效元素
4. **改定位前看引用**：修改前先点开引用数，评估影响面，必要时通知相关流程的负责人
5. **删除前先解引用**：被引用的元素无法直接删，需先在流程中移除引用
