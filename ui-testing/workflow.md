# 流程编排

流程编排是 UI 测试平台的核心工作区。在这里你将测试用例拆解为一系列原子步骤（点击、填写、等待、断言等），通过拖拽排序组合成完整流程，并可进一步引入变量、条件分支与循环，让流程具备业务逻辑级别的判断能力。

平台提供**列表视图**与**画布视图**两种编排模式：前者适合线性流程的快速搭建，后者用节点 + 连线的方式表达复杂分支结构。两种视图共享同一份数据，可随时切换。

![流程编排画布](/screenshots/zh/ui_workflow.png)

## 项目与模块层级

流程编排采用**项目 → 模块 → 流程**三级组织，便于按业务边界归档：

1. 进入 **流程编排** → 左侧树形面板点击 **[+ 项目]**，输入项目名称（如 `ARC RIDE 管理平台`）→ 确定
2. 展开项目 → 点击项目右侧 **[+]** 添加模块（如 `门店管理`、`用户管理`）
3. 选中模块 → 右侧显示该模块下的流程列表；点击 **[新建流程]** 进入编排页

::: tip 命名规范
项目对齐被测系统、模块对齐业务菜单、流程对齐具体操作场景（如 `门店搜索-查询验证`）。统一命名能让后续查找与批量执行更高效。
:::

## 流程基本信息

新建流程时需要填写以下基础配置：

| 配置项 | 说明 |
|--------|------|
| 流程名称 | 业务语义命名，便于读报告 |
| 目标地址 (baseUrl) | 被测系统根地址 |
| 浏览器 | `chromium`（默认）/ `firefox` / `webkit` |
| 运行模式（无头） | 勾选 = 后台静默执行（快，回归用）；不勾选 = 可见浏览器窗口（便于调试） |
| 窗口尺寸 | 默认 1280×720 |
| 录制视频 | 勾选后执行自动录像，结果页可在线回放（默认关闭，按需开启） |
| 目标系统版本 | 记录被测系统版本，写入执行报告环境信息，便于复现 |

视频保留 30 天，过期后结果页会显示「视频已过期」。

## 步骤类型与编排

平台内置 60+ 原子模板，按功能分为六大类。在编排区你可以从左侧模板库**点击或拖拽**模板到步骤列表。

### 导航类

页面级别的导航操作，无需定位元素。

| 模板 | 作用 |
|------|------|
| `navigate` | 打开指定 URL（支持 `wait_until` 等待策略） |
| `go_back` / `go_forward` | 浏览器后退 / 前进 |
| `reload` | 刷新页面 |

### 交互类

最常用的页面元素操作，覆盖点击、输入、选择等场景。

| 模板 | 作用 |
|------|------|
| `click` / `dblclick` / `right_click` | 单击 / 双击 / 右键 |
| `fill` / `type` / `clear` | 填写 / 逐字输入 / 清空 |
| `select` / `check` / `uncheck` | 下拉选择 / 勾选 / 取消勾选 |
| `hover` / `focus` / `blur` | 悬停 / 聚焦 / 失焦 |
| `press_key` | 键盘按键（Enter / Tab / Escape 等） |
| `drag_drop` | 拖拽元素到目标位置 |

### 文件类

`upload`、`upload_multi`、`download`、`set_files` 覆盖文件上传与下载场景。

### 等待与同步类

`wait_for_selector`、`wait_for_timeout`、`wait_for_load_state` 等模板用于显式等待，避免在元素尚未渲染时执行操作导致 flaky。

### 断言类

11 个断言模板（`assert_visible`、`assert_text`、`assert_count` 等），用于验证页面表现。断言失败会触发步骤失败，是判断"测试做对了"的关键。

### 控制类（高级）

`set_variable`、`extract_text`、`condition_if`、`condition_switch`、`loop_while`、`loop_for_each` 等模板提供变量、分支与循环能力，详见下文。

## 步骤配置

每个步骤的通用配置项：

| 配置项 | 说明 |
|--------|------|
| 步骤描述 | 用业务语言说明这一步做什么（必填，便于读报告） |
| 定位来源 | **从元素库选择**（推荐，自动带出定位策略 + 值 + 兜底）或手动填写 |
| 定位策略 | `data-id` / `css` / `text` / `placeholder` / `label` / `role` / `xpath` |
| 定位值 | 对应策略的具体值 |
| 兜底策略 | 主策略定位失败时自动降级（建议配置） |
| 参数 | 模板参数，如 `fill` 的 `value`、`wait` 的 `timeout`、`assert` 的 `expected` |

## 可视化拖拽体验

两种视图共享同一份步骤数据，可随时切换：

- **列表视图**：从左侧模板库点击或拖拽模板到步骤列表，逐个配置。适合**线性流程**的快速搭建。
- **画布视图**：右上角切换到画布模式，用拖拽节点 + 连线的方式编排，支持缩放、自动布局、自动连线。适合**复杂分支**与**全局把控**。

在两种视图下，都支持拖拽调整顺序、复制步骤、删除步骤。

::: tip 列表多匹配的处理
当某步的定位值在页面上匹配到多个元素时，平台默认**取第一个**，并自动记录警告到执行日志。建议在元素库中配置更精确的 `data-testid` 避免歧义。
:::

## 变量系统：步骤间数据传递

变量是分支和循环的前提——条件判断和循环退出都依赖变量值。

**哪些模板能写变量？**

| 模板 | 作用 | 需要定位元素？ |
|------|------|:---:|
| `set_variable` | 直接写入一个变量值 | 否 |
| `extract_text` | 从页面元素提取文本存入变量 | 是 |
| `cookie_get` | 读取浏览器 cookie 存入变量 | 否 |

**怎么引用变量？** 后续步骤用 `${变量名}` 引用，支持两个位置：

- **参数值**：如 `fill` 步骤的 `value = ${订单号}`
- **定位值**：如 `data-id = order-${订单号}`，实现动态定位

::: warning 变量名规范
变量名用英文 + 下划线（如 `user_count`、`login_result`），不要用中文或空格。变量在整个流程内**全局共享**，前置流程设置的变量也能读到。
:::

## 条件分支

### condition_if（二分支）

判断一个条件成立与否，成立走「真」分支，不成立走「假」分支。例如登录后判断 `login_result == ok`：是 → 进业务页；否 → 截图报错。

支持的比较操作符：

| 操作符 | 含义 | 示例 |
|--------|------|------|
| `==` / `!=` | 等于 / 不等于 | `status == 200` |
| `>` `>=` `<` `<=` | 数值比较 | `count > 0` |
| `contains` / `not_contains` | 文本包含 / 不包含 | `url contains "/login"` |
| `is_empty` / `not_empty` | 为空 / 不为空 | `result is_empty` |

### condition_switch（多分支）

根据变量值匹配多个 case 分支，类似编程语言中的 switch。适合"查询结果条数 = 0 / 1 / 多条"这种多场景分流。

## 循环

| 模板 | 退出条件 | 典型场景 |
|------|---------|---------|
| `loop_while` | 条件不满足时退出 | 翻页直到"下一页"按钮禁用 |
| `loop_for_each` | 数组遍历完 | 对表格每一行执行勾选 + 操作 |

循环体内可以嵌套任意步骤，包括再次嵌套分支与循环。配合 `extract_text` 把页面数据抽成 JSON 数组，再用 `loop_for_each` 遍历，可以编排"对查询结果逐条处理"这类贴近真实业务的复杂流程。

::: details 调试断点的范围
`run_from` / `run_until` 调试模式**仅作用于主流程层**，分支与循环内部不支持断点。如需调试循环体，建议先用一个固定的小数组验证逻辑，再换回真实数据。
:::

## 前置流程：登录态复用

几乎所有业务流程都需要先登录。把登录做成**独立流程**，其他流程设为它的前置，是最重要的提效手段。

**机制**：前置流程执行后，浏览器上下文（Cookie / Session / LocalStorage）自动保持给后续流程。也就是说：

- 登录流程跑完拿到登录态 → 后续业务流程无需重复登录
- 多个业务流程可以共用同一个前置登录流程
- 登录逻辑变了，只改登录流程一处，所有依赖它的流程自动跟随

**配置步骤**：

1. 先建一个「XX 登录」流程，步骤含完整登录动作（含验证码识别 `captcha_text`）
2. 编辑业务流程 → 顶部「前置流程」→ 添加「XX 登录」→ 保存
3. 执行业务流程时，系统自动先跑登录流程，再跑本流程

执行记录里会**按流程分组展示**：前置流程的结果在前，本流程在后，一目了然。

## AI 助手：自然语言生成步骤

编排复杂流程时，AI 助手能根据自然语言描述自动生成一整套步骤。点击步骤编排区的 **[AI 助手]** 按钮即可进入，详细用法见 [AI 辅助 UI 步骤生成](../ai/ui-assist.md)。

## 保存与下一步

完成编排后点击 **[保存流程]**。接下来你可以：

- 在流程列表点击 **[执行]** 进行调试（推荐先用"运行到指定步骤"或"单步调试"）
- 配合 [批量执行](./executions.md) 与 [定时任务] 完成回归
- 通过 [元素库](./elements.md) 集中维护定位，降低后续维护成本
