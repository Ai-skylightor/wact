# 执行记录

执行记录是 UI 测试平台的"证据中心"。每一次流程执行（无论是手动触发、批量执行还是定时任务）都会在这里留下一条完整记录，包括每步截图、视频回放、环境版本信息，以及可导出的 HTML / Markdown 报告。

定位失败用例、复现"换版本就挂"的问题、向产品/开发反馈缺陷，都依赖执行记录提供的可视化证据。本节介绍执行记录的核心能力与典型用法。

![执行记录列表](/screenshots/zh/ui_executions.png)

## 执行历史

执行记录按时间倒序排列，每条记录包含以下关键字段：

| 字段 | 说明 |
|------|------|
| 流程名称 | 触发执行的流程（含前置流程会分组展示） |
| 触发方式 | 手动执行 / 批量执行 / 定时任务 / 调试执行 |
| 状态 | 成功 / 失败 / 运行中 / 已终止 |
| 通过率 | 成功步骤数 / 总步骤数 |
| 耗时 | 总执行时间 |
| 触发人 | 执行账号（用户级数据隔离） |
| 环境版本 | 浏览器版本 + 平台版本 + 目标系统版本 |

支持按流程名、状态、触发方式、时间范围筛选，方便快速定位某次回归中的失败用例。

## 每步截图与详情

点击任意一条执行记录进入详情页，可以看到按流程分组的步骤结果：

- **步骤描述**：每步的业务语义说明（来自编排时填写的步骤描述）
- **状态徽标**：成功（绿）/ 失败（红）/ 跳过（灰）
- **截图**：每步执行后的页面截图，失败步骤会高亮标注问题元素
- **耗时**：单步执行时间，用于定位性能瓶颈
- **错误信息**：失败原因（元素未找到 / 超时 / 断言不通过等）
- **定位详情**：实际使用的策略 + 值（含兜底降级路径）

::: tip 前置流程的分组展示
如果流程配置了前置流程（如登录流程），详情页会按流程分组：前置流程的结果在前，本流程在后，便于区分"是登录挂了还是业务挂了"。
:::

## 视频回放

编排流程时勾选**录制视频**选项，执行会自动录像，结果页提供在线播放器。视频能完整还原操作时序，是定位"偶发失败"和"复杂交互问题"的利器。

::: warning 视频保留期
视频默认保留 **30 天**，过期后结果页会显示「视频已过期」。需要长期留档的执行，建议导出 HTML 报告（含截图）归档。
:::

视频录制与无头模式同级开关：

- **无头模式 + 不录视频**：最快，正式回归推荐
- **有头模式 + 录视频**：完整证据，调试与缺陷定位推荐
- **无头模式 + 录视频**：速度略降但仍有视频证据，折中方案

## noVNC 实时画面

有头模式执行时，结果页提供 **noVNC 实时画面**入口，可以远程查看浏览器当前的渲染状态。调试时如同站在浏览器旁边观看，能直观看到：

- 鼠标移动轨迹与点击位置
- 元素高亮提示
- 页面加载过程中的中间态（截图抓不到的瞬间）
- 弹窗、动画等时序敏感的交互

::: tip 何时用 noVNC
截图只能看到执行前后的静态画面，noVNC 适合定位"截图看起来对、但操作时序错了"这类问题。例如：弹窗还没完全渲染就点了确认按钮，导致点击落空。
:::

## 调试执行：终止 / 续跑 / 单步

执行引擎提供多种调试模式，帮助快速定位问题步骤：

| 模式 | 作用 | 适用场景 |
|------|------|---------|
| 普通执行 | 从头到尾顺序执行 | 正式回归 |
| 运行到指定步骤 | 执行到某步后暂停 | 验证前半段逻辑 |
| 从指定步骤继续 | 跳过已验证步骤，从中间开始 | 已定位问题步骤后重试 |
| 单步调试 | 每步执行后暂停，手动确认后继续 | 复杂流程逐步排查 |
| 终止执行 | 强制结束运行中的任务 | 发现明显错误时及时止损 |

::: details 调试断点的范围
`run_from` / `run_until` 仅作用于**主流程层**，分支与循环内部不支持断点。如需调试循环体，建议先用固定小数组验证逻辑，再换回真实数据。
:::

## 批量执行

回归测试时，逐个点执行效率太低。平台支持**勾选多个流程一键并发执行**，统一汇总结果：

1. 在流程编排列表勾选多个流程
2. 点击 **[批量执行]**
3. 系统并发调度，所有流程共享同一批浏览器会话池
4. 结果统一汇总到执行记录，可一键导出汇总报告

批量执行特别适合发版前回归：勾选核心业务流程 → 一键执行 → 查看汇总通过率。

## 报告导出

执行记录支持一键导出 **HTML** 与 **Markdown** 两种格式的测试报告：

- **HTML 报告**：自带样式，含每步截图，可直接发给产品/开发，无需登录平台即可查看
- **Markdown 报告**：纯文本格式，适合粘贴到缺陷跟踪系统（Jira / 禅道）或 Wiki

报告内容包含：

- 流程基本信息（名称、浏览器、目标系统版本）
- 总体结果（通过率、耗时、失败步骤数）
- 每步详情（描述、状态、截图、耗时、错误信息）
- 环境信息（Playwright 版本、平台版本、执行时间）

## 操作日志审计

所有执行相关操作（启动、终止、导出、删除记录）都会写入**操作日志**模块，包含操作人、操作时间、操作对象、操作类型。审计场景下可按操作人或时间范围检索。
