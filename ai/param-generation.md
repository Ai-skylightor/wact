# AI 参数生成

测试数据准备是接口测试中最耗时的环节之一——人凑数据慢、覆盖不全、容易遗漏边界。AI 参数生成能读取 Swagger 接口定义中的参数名、类型、约束（必填、长度、枚举、正则等），智能生成多组符合规则的测试数据，显著降低人工成本。

入口在**仪表盘的 AI 卡片**，支持单接口快速生成与批量异步生成两种模式。生成结果不直接入库，而是进入**审批工作流**，由人工确认后再采纳，保证测试数据质量。

![仪表盘 AI 入口](/screenshots/zh/dashboard.png)

## 工作原理

AI 参数生成的核心流程：

```
读取 Swagger 接口定义
  ↓ 提取参数：name / type / required / length / enum / pattern
AI 模型按参数约束生成多组数据
  ↓ 每组数据 = 一条测试用例的入参
返回 JSON 数组（多级容错解析）
  ↓
进入审批队列，人工确认
  ↓ 通过后入库为正式用例
```

AI 在生成时会综合考虑：

- **类型合规**：string / int / boolean / array / object 等类型不混淆
- **约束满足**：必填字段必给值、长度不超限、枚举只取合法值、正则匹配
- **场景覆盖**：正常值、边界值、特殊字符（如手机号带 +86）、空字符串等
- **业务合理**：手机号符合号段、邮箱符合格式、日期符合格式

## 单接口生成

最快的用法——针对单个接口生成测试数据：

1. 进入接口详情页 → 点击 **[AI 生成参数]** 按钮
2. 系统自动提取该接口的参数定义，构造提示词
3. AI 模型生成 N 组测试数据（默认 5 组，可调整）
4. 在结果区**预览**每组数据的参数值
5. 勾选要采纳的数据 → 点击 **[入库]** → 写入该接口的用例列表

::: tip 预览再入库
生成结果不会直接写入用例库，必须经过预览 + 勾选 + 入库三步。这是有意设计的"人工审批"环节——AI 偶尔会生成不合理的值（如把"年龄"生成成 999），人工把关可以过滤掉这类噪音。
:::

## 批量生成（异步任务）

当需要对一个项目下的**多个接口**批量生成参数时，单接口模式效率太低。批量生成以**异步任务**形式执行：

1. 在仪表盘 AI 卡片选择 **[批量参数生成]**
2. 选择目标项目 / 模块（可多选）
3. 配置生成参数：
   - 每个接口生成几组数据（默认 5 组）
   - 是否覆盖已有用例
   - AI 模型（默认走用户配置）
4. 提交后任务进入**异步队列**，立即返回任务 ID
5. 在任务管理页查看进度（已处理 / 总数）

### 异步任务机制

批量生成采用异步设计的原因：

- **AI 调用耗时**：单接口生成约 5-15 秒，100 个接口串行需 10+ 分钟
- **避免请求超时**：HTTP 请求有超时限制，长任务必须异步化
- **可中断恢复**：任务失败可从断点续跑，不必从头开始

任务进度面板显示：

| 字段 | 说明 |
|------|------|
| 任务 ID | 唯一标识 |
| 总接口数 | 本次任务覆盖的接口数量 |
| 已完成 | 已生成完毕的接口数（实时更新） |
| 失败数 | 因 AI 超时 / 解析失败等原因失败的接口 |
| 状态 | 排队中 / 运行中 / 已完成 / 部分失败 |
| 进度条 | 已完成 / 总数的百分比 |

::: warning 任务并发限制
为避免压垮 AI 模型服务（特别是本地 Ollama），批量任务默认**串行执行**（一个接口生成完再生成下一个）。如需提速，可在配置页切换到响应更快的云端模型。
:::

## 生成结果审批

无论是单接口还是批量生成，结果都需要**人工审批**才会正式入库。审批工作流如下：

### 审批入口

任务完成后，在任务管理页点击对应任务 → 进入**结果审批**视图。

### 审批操作

| 操作 | 作用 |
|------|------|
| **逐条预览** | 查看每条生成数据的参数值，标注 AI 推理依据 |
| **单条通过** | 采纳该条数据为正式用例 |
| **单条驳回** | 丢弃该条数据 |
| **单条编辑** | 在 AI 生成基础上微调参数值后再采纳 |
| **批量通过** | 一次通过所有未审数据（适合批量生成后整体认可的场景） |
| **批量驳回** | 一次驳回所有未审数据 |

::: tip 批量通过 + 局部编辑
推荐的工作流：先**批量通过**整体方向正确的数据，再对个别不合理的条目做**单条编辑**微调。这比逐条审核快得多，又能保证关键数据的准确性。
:::

## 提示词与多级容错解析

AI 返回的内容是文本，需要解析成结构化 JSON 才能入库。平台采用**4 级容错解析**策略：

1. **直接 JSON 解析**：尝试把整段返回当作 JSON 解析
2. **代码块提取**：从 ```json ... ``` 代码块中提取
3. **正则匹配**：用正则定位最外层 `{...}` 或 `[...]`
4. **字段拼装**：逐字段提取 name / value 拼装成结构

::: details 为什么需要多级容错
大模型不是百分百遵守"只返回 JSON"的指令——有时会带前后说明文字、有时会包代码块、有时会用单引号、有时甚至混入注释。4 级容错能把生成成功率从约 70% 提升到 95% 以上，显著减少人工重试。
:::

## 提示词模板管理

AI 参数生成使用的提示词**以模板形式管理**，可自定义、可复用，不必每次手写。

![AI 提示词模板管理](/screenshots/zh/ai_prompts.png)

### 入口

在测试用例编辑弹窗中点击 **「查看提示词」** 按钮，直接跳转到提示词模板管理页（该页面不在左侧导航显示，属于 AI 生成的配套管理入口）。

### 模板字段

| 字段 | 说明 |
|------|------|
| 名称 | 模板名称，便于识别 |
| 分类 | 当前为**接口参数生成**，后续将扩展断言生成、用例生成等场景 |
| 描述 | 模板用途说明 |
| 变量数量 | 模板中 `{变量}` 占位符的个数（生成时自动替换为实际参数定义） |
| 状态 | 启用 / 停用 |

### 支持的操作

- **新建模板**：编写自己的提示词（含变量占位符）
- **编辑 / 删除**：调整已有模板内容，或删除不需要的
- **批量删除 / 全选**：清理废弃模板

::: tip 什么时候需要自定义模板
内置默认模板已能覆盖绝大多数接口。当团队有特殊约定（如"所有金额字段必须生成两位小数"、"手机号必须虚拟号段"）时，复制默认模板改名后追加约束，比每次手动补充更省事。
:::

## 典型场景

### 场景一：新接口快速造数据

后端刚交付一个新接口，前端还没联调，测试需要先准备数据：

1. 导入 Swagger → 接口列表出现新接口
2. 进入接口详情 → **[AI 生成参数]**
3. 5 秒内拿到 5 组数据，预览确认合理
4. 入库 → 立即可用于接口测试

### 场景二：项目级回归数据准备

发版前需要为整个模块的所有接口准备回归数据：

1. 仪表盘 AI 卡片 → **[批量参数生成]**
2. 选择目标模块（含 50 个接口）
3. 提交异步任务，去做别的事
4. 半小时后回来，任务已完成
5. 进入审批视图，**批量通过**整体合理的数据
6. 对个别不合理的条目做单条编辑或驳回

### 场景三：补充边界用例

已有几条正常用例，但边界覆盖不足：

1. 进入接口详情 → AI 生成参数
2. 在提示词中追加"重点生成边界值、异常值"
3. AI 会生成空字符串、超长字符串、负数、0、最大值等边界数据
4. 审批入库，补充到现有用例集

## 常见问题

**Q：AI 生成的数据是否符合业务规则？**
A：符合**参数定义层面的规则**（类型、长度、枚举、正则），但不一定符合**深层业务规则**（如"该手机号必须是已注册用户"）。前者由 AI 保证，后者需要人工把关。

**Q：批量任务失败了怎么办？**
A：任务进度面板会显示失败的接口列表，可单独重试这些接口，不必整体重跑。

**Q：生成一条用例要多久？**
A：默认模式（本地 Ollama）约 5-15 秒；API 模式取决于云端模型，DeepSeek 等通常 2-5 秒。
