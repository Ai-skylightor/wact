# AI 辅助 UI 步骤生成

UI 测试流程编排里最耗时的是"把一个业务场景拆解成几十个原子步骤"——点哪个元素、填什么值、在哪步加等待、在哪步断言。AI 辅助 UI 步骤生成能根据自然语言描述或场景引导，自动生成一整套步骤，相比纯手点效率提升数倍。

入口在**流程编辑页步骤编排区**的 **[AI 助手]** 按钮。生成的步骤里每个元素的 locator 都来自当前元素库的真实元素，不会编造。生成结果可预览、可微调、可追加，最终由人工确认后并入流程。

## 两种生成模式

| 模式 | 适用 | 怎么用 |
|------|------|--------|
| **场景引导** | 标准操作（登录 / 查询 / 新增 / 编辑 / 删除） | 选场景 → 加载元素库 → 在骨架表单里选元素、填值 → 生成 |
| **自定义（自然语言）** | 复杂 / 非标准流程（弹窗、多步、特殊交互） | 选「自定义」→ 按结构化模板填写 → AI 生成 |

::: tip 怎么选模式
能用场景引导解决的就用场景引导（快、稳定）；遇到弹窗、二次确认、多步联动这类标准场景没覆盖的交互，再用自定义模式描述。两种模式可以混用：先用场景引导生成主体，再用自定义模式补充细节。
:::

## 场景引导模式

平台内置 5 种标准场景骨架，每个场景已预置步骤序列，你只需在骨架基础上选择元素、填值。

### 内置场景

| 场景 | 预置步骤序列 |
|------|------------|
| **登录** | 填账号 → 填密码 → （可选）填验证码 → 点登录 → 断言登录成功 |
| **查询** | 填关键字 → 点查询 → 等待结果 → 断言结果出现 |
| **新增** | 点新增 → 填表单各项 → 点保存 → 断言成功提示 |
| **编辑** | 点编辑 → 修改表单 → 点保存 → 断言修改生效 |
| **删除** | 勾选记录 → 点删除 → （可选）确认二次弹窗 → 断言记录消失 |

### 操作步骤

1. 进入流程编辑页 → 点击 **[AI 助手]** → 选择 **场景引导** 模式
2. 在元素库项目 / 模块下拉里选中目标模块 → 系统自动加载该模块的元素
3. 在每步的「定位元素」下拉里**从元素库选元素**（自动带出定位策略 + 值 + 兜底）
4. 在「值」输入框填具体内容（如手机号 `13800138000`、搜索关键字 `门店A`）
5. 点击 **[直接生成]**（不走 AI，按骨架直接组装）或 **[AI 生成]**（AI 在骨架基础上补等待 / 断言）

::: tip 直接生成 vs AI 生成
**直接生成**不走 AI，按骨架硬编码组装，速度快，适合标准场景；**AI 生成**会让 AI 在骨架基础上**补等待、补断言**，生成更完整的步骤序列。对稳定性要求高的场景推荐 AI 生成。
:::

## 自定义模式（自然语言，重点）

用于复杂交互——弹窗、多步联动、特殊交互等标准场景没覆盖的情况。选「自定义」后出现**结构化输入区**，按模板填得越完整，生成质量越高。

### 结构化输入字段

| 字段 | 必填 | 说明 | 示例 |
|------|:---:|------|------|
| **操作步骤** | 是 | 按手动点击的真实顺序列，每步一行 | 1. 勾选第一个用户<br>2. 点击绑定门店<br>3. 选第一个门店<br>4. 点击确认 |
| **每步后的现象** | 否 | 哪些步骤会弹窗 / 跳转 / 出现新按钮 | 第 2 步弹出门店弹窗；第 4 步点确认后又弹了二次确认气泡 |
| **不确定的点** | 否 | 你拿不准的地方（往往就是难点） | 第 4 步要不要再确认一次 |
| **成功标志** | 否 | 怎么算做对（AI 会据此生成断言） | 弹窗都关闭，用户行出现门店名 |

### 填写要点

::: tip 「每步后的现象」是关键
像"点了又弹个确认框"这种**隐式交互**，写出来 AI 才会补成独立步骤，否则极易遗漏。流程失败 80% 发生在这种隐式交互上——你以为一步能完成，实际要点两次。
:::

::: tip 「成功标志」驱动断言生成
填写"成功标志"会让 AI 据此生成 `assert_visible` / `assert_text` 等断言步骤，让测试不只是"点完了"而是"验证做对了"。没有断言的流程等于没有验证。
:::

::: warning 真实元素，不会编造
AI 生成的步骤里，每个元素的 locator 都来自**当前元素库 / 页面抓取的真实元素**，不会凭空编造选择器。如果某步需要的元素不在元素库里，AI 会标注"未找到匹配元素"，提示你先去录制。
:::

### 生成结果处理

生成后可在结果区**预览**：

- 每一步的描述、定位元素、参数值
- AI 自动补的等待步骤（标记为"AI 推断"）
- AI 自动补的断言步骤（基于"成功标志"）

确认无误点 **[应用]** → 步骤**追加**到当前流程（不会覆盖已有步骤），再在画布 / 列表视图里微调顺序与细节。

## 页面分析能力

除了基于描述生成步骤，AI 还能**主动分析页面结构**，辅助你理解陌生页面：

### 页面截图 + DOM 分析

- AI 通过 Playwright 打开目标页面 → 截图 + 读取 DOM
- 识别页面上的可交互元素（按钮、输入框、链接、表格等）
- 推断元素的业务用途（"这个按钮应该是提交"、"这个输入框应该是搜索"）

### 适用场景

- **接入新系统时**：陌生页面，不知道有哪些可操作元素
- **页面改版后**：确认新页面的元素结构，更新元素库
- **复杂弹窗**：弹窗里的元素难以人工梳理，AI 辅助识别

::: details AI 页面分析的局限
AI 分析基于截图 + DOM，但**无法理解业务语义**——它能识别"这是个按钮"，但不一定能判断"这是查询按钮还是重置按钮"。页面分析的结果需要人工业务语义复核后再入库。详细局限与建议见 `ai_ui_test_design.md`。
:::

## 生成质量的影响因素

AI 生成步骤的质量受以下因素影响，提前了解能显著提升一次通过率：

| 因素 | 高质量输入 | 低质量输入 |
|------|-----------|-----------|
| **元素库完备性** | 元素库已录制齐全，AI 能直接引用 | 元素库稀疏，AI 标注"未找到" |
| **操作步骤描述** | 每步动作 + 目标元素明确 | 描述模糊（"操作一下"、"处理弹窗"） |
| **现象说明** | 标注弹窗 / 跳转 / 二次确认 | 不写现象，AI 漏补步骤 |
| **成功标志** | 明确写出验证点 | 不写，AI 不会生成断言 |
| **原型图 / 文档** | 有原型图参考，AI 锁定元素准确 | 无原型图，AI 需探索页面 |

::: warning 上游瓶颈
根据 `ai_ui_test_design.md` 的实测：**有原型图 + 优质需求文档**时，AI 一次通过率可达 90%+；**无原型图 + 文档质量差**时，一次通过率可能降到 40~50%。提升原型图与文档质量是放大 AI 价值的关键上游投入。
:::

## 典型场景

### 场景一：标准登录流程

1. 先在元素库录制登录页元素（账号框、密码框、登录按钮、验证码框）
2. 流程编辑页 → AI 助手 → 场景引导 → **登录**
3. 选元素库的登录页模块 → 在骨架表单里选元素、填账号密码
4. **[AI 生成]** → AI 补"等待首页加载""断言用户头像出现"
5. 应用 → 追加到流程 → 保存为「XX 登录流程」
6. 把这个流程设为其他业务流程的**前置流程**，登录态自动复用

### 场景二：复杂绑定流程（自定义模式）

业务场景：在用户列表勾选用户 → 点绑定门店 → 在弹窗选门店 → 点确认 → 又弹二次确认 → 再点确认

1. AI 助手 → 自定义模式
2. 操作步骤：
   ```
   1. 勾选第一个用户
   2. 点击"绑定门店"
   3. 在弹窗里选第一个门店
   4. 点击"确认"
   ```
3. 每步后的现象：
   ```
   第 2 步弹出门店选择弹窗
   第 4 步点击后又弹出二次确认气泡
   ```
4. 不确定的点：第 4 步后是否需要再点一次确认
5. 成功标志：弹窗全部关闭，用户行显示已绑定的门店名
6. **[AI 生成]** → AI 会生成包含二次确认处理的完整步骤 + 断言
7. 预览确认 → 应用

### 场景三：陌生页面快速摸底

接入一个新系统，对页面结构不熟：

1. AI 助手 → 页面分析
2. 输入页面 URL → AI 打开页面截图 + 读 DOM
3. 返回页面元素清单 + 业务用途推断
4. 基于分析结果决定哪些元素需要录制入库
5. 切到元素库录制 → 回到流程编排用 AI 助手生成步骤

## 生成后的微调建议

AI 生成不等于完美，应用后通常还需要微调：

1. **检查定位策略**：AI 默认选的策略不一定最优，关键元素改成 `data-testid`
2. **补充兜底策略**：AI 不会自动配兜底，建议手动加上
3. **调整等待时间**：AI 补的等待可能过长或过短，按实际网络情况调
4. **细化断言**：AI 补的断言较粗糙，关键业务点应配更精确的断言
5. **首次执行用调试模式**：用单步调试走一遍，确认每步行为符合预期

## 常见问题

**Q：AI 生成的步骤里有"未找到元素"怎么办？**
A：说明该元素不在当前元素库。先去元素库录制拾取该元素，回到 AI 助手重新生成，或在画布里手动把这一步的定位改成已录制的元素。

**Q：生成结果与预期差太远怎么办？**
A：检查输入描述是否完整，特别是「每步后的现象」与「成功标志」两栏。这两栏空着不写，是生成质量低的最常见原因。

**Q：可以用 AI 生成整个回归集吗？**
A：可以但要谨慎。建议按业务场景拆分，每次生成一个独立场景的步骤，分别审批入库。一次性生成整个回归集容易导致质量失控。

**Q：AI 生成的步骤里有变量吗？**
A：默认不会主动用变量。如果需要变量（如从列表提取订单号、后续步骤引用），在「不确定的点」或「成功标志」里写明"需要记录订单号供后续使用"，AI 会补 `extract_text` 步骤。
