# 用例评审

> AI 先审 + 人工终审 + 多人投票（3 过 2），两级门禁保证 AI 生成用例的质量。只有全部通过的批次才能导出 Excel。

## 功能介绍

「用例评审」是 [AI 用例生成](./web-case-generation.md) 的质量把关环节。完整流程：

1. **AI 自动评审**（第一级）：AI 对每条用例打质量分（0-100）、列出问题、给出建议
2. **AI 自动优化**（负责人操作）：AI 根据评审发现的问题，自动修复用例内容（步骤/预期/前置条件）
3. **人工终审**（第二级）：3 名评审人投票，2 人通过 → 最终通过；无法通过则驳回修改

通过评审的用例 `review_status = approved` 才可导出 Excel；驳回的用例需负责人修改后重新走评审流程。

## 完整流程

```
负责人生成用例 → 配置评审人（3人）
  ↓
AI 自动评审（每条用例：质量分 + 问题清单 + 建议）
  ↓
负责人可选：✨ AI 优化（根据评审问题修复内容）
  ↓
评审人投票（3过2）：
  2人通过 → approved ✅（可导出）
  2人驳回 → rejected ❌（负责人修改后重新评审）
  未达标 → pending_review ⏳（等其他评审人）
```

## 角色与权限

| 角色 | 说明 |
|------|------|
| **负责人**（生成者） | 生成用例、配置评审人、编辑/优化用例、重跑 AI 评审 |
| **评审人**（被分配） | 投票通过/驳回用例、查看评审历史 |
| **旁观者** | 只能查看，不能操作 |

### 按钮权限矩阵

| 操作 | 负责人 | 评审人 | 状态要求 |
|------|--------|--------|----------|
| 配置评审人 | ✅ | ❌ | — |
| ✏️ 编辑用例 | ✅ | ❌ | 未通过 |
| 🔄 重跑 AI 评审 | ✅ | ❌ | 选中待审/驳回的 |
| ✨ AI 优化 | ✅ | ❌ | 选中待审/驳回的 |
| ✅ 通过/❌ 驳回 | ❌ | ✅ | 待审 + AI 已完成 + 未投票 |
| 批量通过/驳回 | ❌ | ✅ | 选中待审 + 未投票 |
| 下载 Excel | ✅ | ❌ | 全部通过 |

## 配置评审人

### 在哪配置

在「AI 用例生成」→「结果记录」页面，每条已完成的批次右侧有「👥 评审人」按钮。

### 配置规则

- 每个批次独立配置（不同需求可配不同评审人）
- 最多 3 名评审人
- 生成者不能选择自己作为评审人
- 通过票数默认 2（可改为 1 或 3）

## 评审中心

### 入口

「AI 用例生成」→「用例评审」侧边栏。

![评审中心](/screenshots/zh/ai_case_review.png)

评审中心展示：
- **负责人**看到的：自己生成的批次
- **评审人**看到的：分配给自己评审的批次

每张批次卡片显示：

- 生成者名称 + 时间

- 评审进度（我已评审 N/M，排除已被其他人审完的）

## 评审通知

AI 把整批用例评审跑完后，系统自动给该批次的评审人各发一条**站内通知**，提醒前来投票。

- 侧边栏用户名旁有一个 🔔 铃铛，未读通知数会以红色数字徽标显示（每 60 秒刷新一次）
- 点击铃铛展开通知列表，点某条通知 → 自动标记已读并跳转到对应批次的评审明细
- 同一批次对同一评审人 1 小时内不重复发送（避免重复打扰）

::: tip 前提
只有**配置过评审人**的批次，AI 评审完成后才会发通知。没配评审人的批次不发。
:::

### 企业微信群推送

配置过企业微信机器人 webhook 后，群里有两次自动播报，构成完整生命周期：

| 时机 | 播报内容 |
|------|----------|
| **邀请评审**（评审人已配 + AI 评审跑完，两个条件都满足的那一刻） | 批次名 / 负责人 / 评审人 / 用例数 / AI 评审概览 + 可点击的「查看」深链 |
| **全部通过**（批次所有用例都通过评审的那一刻） | 「✅ 全部通过」+ 负责人 / 评审人 / 用例数 + 可点击的「查看用例详情」深链 |

- webhook 配置在 `system_config` 的 `wechat_review_webhook`；未配置则跳过推送。
- 每次播报都有去重（邀请评审用 `wechatPushed`，全部通过用 `approvedPushed`），不会重复发。
- 如果全部通过后又编辑/新增用例回到待审，标记会清除，重新全部通过时会再播报一次。

## 用例管理（负责人）

负责人（批次创建者）除了评审，还能直接**管理用例**：

- **➕ 新增用例**：评审明细左下角点「新增用例」→ 填标题/优先级/类型/标签/前置条件/步骤/预期 → 保存。人工新增的用例标 `source=manual`，**走和 AI 生成完全一样的流程**（自动触发 AI 评审 → 进人工投票队列）。
- **🗑 删除用例**：用例详情里点「删除」。**规则：只要这条用例还没被任何审批人投过票（通过/驳回都算）就能删；一旦有人评审过就锁定不能删**（AI 评审不影响删除门槛）。删除后批次用例数和评审状态自动重算。

::: warning 权限
新增/删除只有**该批次的负责人**能做；其他评审人和普通用户看不到按钮，调用接口也会被拒绝。超管对他人批次为只读。
:::

## 批次评审明细

### 左侧：用例列表

- 状态图标：⏳ 待审 / ✅ 通过 / ❌ 驳回
- AI 建议左边框色：绿=建议通过 / 橙=建议修改 / 红=建议驳回
- checkbox：只有待审且未投票的可选（负责人可选驳回的）
- 左下角操作区（按角色）：
  - 负责人：全选 | ➕ 新增用例 | 🔄 重跑选中 | ✨ 优化选中
  - 评审人：全选 | 批量通过 | 批量驳回

### 右侧：用例详情

#### 用例信息

完整用例内容（标题、优先级、类型、场景、前置条件、步骤、预期）。负责人可点「编辑用例」修改；**未被评审过**的用例还可点「🗑 删除」。

#### 🤖 AI 评审

- 质量分（0-100）+ 新旧分数对比
- AI 建议（建议通过 / 建议修改 / 建议驳回）
- 五维度评分：步骤可执行性 / 预期可验证性 / 场景覆盖度 / 前置条件合理性 / 语言规范性
- 问题清单（按严重度 🔴critical / 🟠major / 🟡minor）

#### 👤 评审人投票

3 名评审人各自状态 + 票数汇总。评审人可投票（通过/驳回），需填写理由。

#### 📋 评审历史

按轮次分组展示所有评审记录（AI + 人工），完整审计链。

## AI 自动优化

负责人可以选中用例，点「✨ 优化选中」，AI 会：
1. 根据评审发现的问题，修复用例内容
2. 步骤更具体（明确操作路径、按钮名称）
3. 预期更可验证（给出具体校验点）
4. 前置更充分（明确测试数据准备）
5. 去掉后端术语

优化后分数应该提升（因为是内容真的改好了，不是重新碰运气）。

**约束**：已通过（approved）的用例不能优化（永久锁定）。

## 驳回后 AI 自动重写

用例被人工终审驳回（2 票驳回）后，**无需人工操作**，系统自动：

1. 收集驳回依据：最新 AI 评审发现的问题 + 本轮所有评审人的驳回理由
2. AI 针对性重写用例（重点回应评审人的驳回理由，不只是修 AI 问题）
3. 进入新一轮审批：`投票轮次 +1`，旧投票保留在历史，评审人重新投票
4. 自动触发 AI 复审（5 个维度重新打分）

整个过程中，该用例显示「🤖 AI 自动重写中」状态；同批次其他用例（已通过 / 审核中）不受影响。

### 重写次数上限

为避免 AI 和评审陷入死循环空转，设有上限（默认 5 次，可在 `system_config` 表的 `web_case_auto_resubmit_limit` 配置）：

- 连续自动重写达到上限仍未通过 → **停止自动流程**，用例留在 `rejected`，提示「AI 已自动重写 N 次仍未通过，需负责人介入」
- 此时负责人可在评审明细页手动编辑用例，编辑后重新进入评审流程

::: tip 正常情况不受影响
绝大多数用例一次重写就能通过复审，上限只是兜底保护，防止极端情况下反复消耗。
:::

## 投票规则

### 3 过 2

| 投票情况 | 结果 |
|----------|------|
| 2 通过 + 1 驳回 | ✅ approved（先到 2 票通过为准） |
| 1 通过 + 2 驳回 | ❌ rejected（不可能凑够 2 票了） |
| 1 通过 + 1 驳回 | ⏳ pending（等第 3 票） |
| 2 通过 + 0 驳回 | ✅ approved |

### 投票轮次

用例内容修改（编辑/优化）后，投票轮次 +1：
- 旧投票保留在评审历史里（完整审计链）
- 但不参与新一轮的投票统计
- 评审人可以重新投票（不报"已评审过"）

## 用例生命周期

```
生成 → pending_review
  ├─ 2人通过 + 0驳回 → approved（永久锁定，可导出）
  ├─ 有人驳回，剩余不够达标 → rejected
  │    ├─ AI 自动重写（auto_resubmitting）→ vote_round+1 → pending_review → 重新评审
  │    │    └─ 达重写上限仍未通过 → rejected（需负责人介入）
  │    └─ 负责人手动编辑/优化 → vote_round+1 → pending_review → 重新评审
  └─ 未达标 → pending_review（等其他人投）
```

## 下载 Excel

下载是**最后一步**——只有批次所有用例都通过评审（`reviewStatus = approved`）才能点击下载，否则按钮置灰。

## 前置条件

- AI 模型需在 [AI 配置](./model-config.md) 页面配置好
- 负责人生成用例后需在「结果记录」配置评审人
- 评审人需被负责人分配后才能看到批次
