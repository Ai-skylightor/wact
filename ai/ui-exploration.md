# AI 网站探索

接入一个新系统、面对一个陌生页面时，最高效的起手式是什么？**AI 网站探索**让你只需填一个 URL（外加可选的登录信息），AI 就会用无头浏览器打开页面 → 抓取全部可交互元素 → 按可测性分类 → 自动规划测试场景 → 生成每套流程的步骤 → 落库成可直接执行的 workflow。

与 [AI 辅助 UI 步骤生成](./ui-assist.md) 的区别：**步骤生成**是在流程编辑器里「描述一个场景 → 生成这一个场景的步骤」，你心里得先有场景；**网站探索**是「给个 URL → AI 自己发现有哪些场景值得测」，连场景规划都替你做了，适合从零起手批量铺流程。

入口在 **UI 自动化 → 流程编排** 工具栏右侧的 **[🤖 AI 探索]** 按钮。

## 工作原理

```
你填 URL（+登录信息）
        ↓
  ① 启动无头浏览器          Chromium 无头打开目标页面
        ↓
  ② 自动登录（如有）         用你提供的账号密码走登录流程
        ↓
  ③ 抓取页面元素            扫描 DOM，提取按钮 / 输入框 / 表格 / 链接等可交互元素
        ↓
  ④ 元素分类               按可测性分组：表单、按钮、表格操作、搜索、导航
        ↓
  ⑤ AI 场景规划             大模型根据元素分布，规划「值得测」的场景清单
        ↓
  ⑥ AI 步骤生成             每个场景生成一整套步骤（含等待 / 断言）
        ↓
  ⑦ 防编造校验              校验每个 locator 都来自真实抓取的元素，编造的步骤被剔除
        ↓
  ⑧ 落库为 workflow          生成结果保存到当前项目 / 模块，状态为「草稿」
```

整个流程**异步执行**，启动后立即返回一个探索 ID，前端每 2 秒轮询一次进度，你可以实时看到每一步的状态（待开始 / 进行中 / 已完成 / 失败）和发现元素数、生成流程数。

## 怎么用

### 1. 准备：选中项目 / 模块

在左侧树导航里**先选中目标项目 / 模块**。生成的流程会归类到这里；不选也能用，但生成的流程会变成「无主」，后续不好管理。

::: tip 先建后归
强烈建议先选好项目 / 模块再探索。探索弹窗顶部会提示当前归属（项目 ID / 模块 ID），没选时会警告。
:::

### 2. 填写目标 URL

点 **[🤖 AI 探索]** → 弹窗里填**目标页面 URL**（必填），即你想让 AI 探索的那个页面地址。

::: tip 填哪个页面
填你**真正想测的业务页面**，比如后台首页、某个列表页、某个表单页。不要填登录页——登录页交给「登录信息」字段处理。
:::

### 3. 填登录信息（可选，大多数后台系统必填）

如果目标页面需要登录才能访问，填这三项，AI 会**先登录再导航到目标页面**：

| 字段 | 说明 |
|------|------|
| **登录页 URL** | 登录页地址，如 `https://your-app.com/login` |
| **用户名** | 测试账号 |
| **密码** | 测试账号密码 |

::: warning 必须用测试账号
AI 探索用你提供的账号**真实登录**目标系统。务必使用专用的测试账号，不要用生产账号；测试账号最好没有敏感数据访问权限，避免探索过程中触发意外的写操作（虽然探索以读取为主，但有些页面的按钮点击会产生副作用）。
:::

### 4. 点「开始探索」

点 **[🚀 开始探索]**，进度区立即展开，实时显示：

- **进度条**：已完成步骤占比
- **步骤列表**：每一步的图标（✅⏳❌）+ 名称 + 详情
- **统计**：发现元素数 · 生成流程数，生成后可点链接直接打开流程

### 5. 完成后处理

探索完成后：

1. 流程列表**自动刷新**，新生成的流程出现（带 `ai_explored` 标签，状态为「草稿」）
2. 点流程名进编辑器 → **人工复核**每个步骤（AI 生成的步骤质量依赖页面结构清晰度）
3. 按需微调定位策略、补兜底、调等待、细化断言
4. 复核满意后保存为正式流程，即可执行

## AI 探索能测什么

AI 把抓到的元素按可测性分成 5 类，据此规划场景：

| 元素分类 | 探索会做什么 |
|---------|-------------|
| **表单** | 规划「填写表单 → 提交 → 验证」类场景 |
| **按钮** | 规划「点击关键按钮 → 观察结果」类场景 |
| **表格操作** | 规划「分页 / 排序 / 行内操作」类场景 |
| **搜索** | 规划「输入关键字 → 触发搜索 → 验证结果」类场景 |
| **导航** | 规划「切换菜单 → 验证页面切换」类场景 |

::: details 探索的边界
AI 探索**以单个页面为粒度**：它打开你给的 URL，分析这一页有哪些可测交互，规划这一页的场景。它**不会自动跳转到其它页面**去继续探索（depth=1）。如果你需要覆盖多页面的端到端流程（如「下单 → 支付 → 查看订单」），需要针对每个关键页面分别探索，再在流程编排里手动串起来。
:::

## 防编造机制

AI 生成最大的风险是**编造**——模型凭空捏造一个页面上不存在的元素选择器，导致流程一执行就「元素未找到」。本平台内置防编造校验：

- 每个生成步骤的 locator 都会与**实际抓取的元素清单**比对
- 匹配不上的步骤被**直接剔除**，不进入最终结果
- 所以最终落库的流程，每个元素都「真实存在」（但不保证定位策略最优，仍需人工复核）

## 质量影响因素

探索结果的质量取决于页面本身的结构清晰度：

| 因素 | 探索效果好 | 探索效果差 |
|------|-----------|-----------|
| **页面元素语义** | 元素有 `id` / `name` / `data-testid` | 纯 `div` + `class` 套娃，无语义属性 |
| **登录复杂度** | 标准账号密码登录 | 验证码 / 短信 / 扫码登录（AI 登录会失败） |
| **页面加载方式** | 服务端渲染，DOM 一次到位 | 重 SPA，元素异步加载，需长等待 |
| **反爬机制** | 无 | 检测无头浏览器、人机校验 |

::: tip 登录失败时的降级
如果 AI 自动登录失败（验证码、风控等），探索仍会继续——但抓到的是登录页而非目标页的元素，规划出的场景没意义。遇到这种情况：改用无登录的页面探索，或者先用 [流程编排](../ui-testing/workflow.md) 手动建一个登录流程设为前置，再探索登录后的页面。
:::

## 与其它 AI 功能的关系

| 功能 | 入口 | 干什么 | 输出 |
|------|------|--------|------|
| **AI 网站探索**（本页） | 流程编排 → AI 探索 | 给 URL，AI 自己发现场景 | 一整套草稿流程 |
| [AI 辅助步骤生成](./ui-assist.md) | 流程编辑器 → AI 助手 | 描述一个场景，生成这一套步骤 | 单个流程的步骤 |
| [AI 参数生成](./param-generation.md) | 接口测试 → 参数填充 | 生成接口测试数据 | 测试数据 |

典型组合用法：**先用网站探索从零铺一批流程** → 对其中不满意的手动删步骤 → 用**步骤生成**补全 / 优化关键流程 → 用**参数生成**填充动态参数。

## 常见问题

**Q：探索卡在「启动浏览器」一直不动？**
A：服务器上没装 Playwright 的 Chromium 依赖。在容器 / 服务器上执行 `playwright install chromium` 安装浏览器，并确保容器有足够的共享内存（`--shm-size=2g`）。

**Q：登录步骤失败怎么办？**
A：检查登录信息是否正确、目标系统是否需要验证码。如果是验证码登录，AI 无法自动登录，建议探索无需登录的页面，或先手动建登录流程作为前置。

**Q：探索完成了但生成 0 个流程？**
A：可能页面元素抓取成功但 AI 场景规划没识别出可测场景（页面太简单 / 元素语义不足）。换个元素更丰富的页面试，或在流程编排里用 [步骤生成](./ui-assist.md) 手动描述场景。

**Q：生成的流程能直接执行吗？**
A：**不能直接执行**。生成的流程状态是「草稿」，每个步骤都经过防编造校验（元素真实存在），但定位策略、等待时间、断言可能需要人工微调。建议先在调试模式下单步走一遍确认无误，再正式执行。

**Q：探索会修改目标系统的数据吗？**
A：探索以**读取 + 点击为主**，但如果页面上的某个按钮点击会触发写操作（如「提交」按钮），AI 可能会点。务必用隔离的测试环境 + 测试账号，避免在生产环境探索。
