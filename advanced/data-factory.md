# 数据工厂

数据工厂（Data Factory）是接口测试平台内置的测试数据生成与管理模块。它解决的是测试自动化里最普遍的痛点：**用例要的"动态测试数据"放哪里、怎么生成、怎么引用**。

传统做法是把测试数据硬编码进用例（一旦跑过就被消费，下一次执行就是脏数据），或者维护一份 Excel 表（更新慢、版本乱）。数据工厂则提供了一种新范式——用树形结构组织数据资产、用规则占位符描述生成逻辑、用例执行时按需即时生成、跑完即弃。

![数据工厂主界面](/screenshots/zh/data_factory.png)

## 设计思路

数据工厂用**三级树形结构**组织数据，对应业务里的"在哪个项目、要哪类数据、具体的字段"：

```
📦 项目（Project）
└── 📁 参数类型（Parameter Type / 文件夹）
    ├── 参数类型：用户身份信息
    │   ├── 手机号      → ${phone()}
    │   ├── 邮箱        → ${email()}
    │   └── 身份证号    → ${id_card()}
    └── 参数类型：订单测试数据
        ├── 订单编号    → ${random_string(12)}
        └── 金额        → ${random(1-9999)}
```

- **项目**：与接口测试的项目对齐，保证数据隔离
- **参数类型**：相当于文件夹，按业务域归类（用户、订单、商品…）
- **参数**：一条具体的字段定义，包含参数名和参数值（值可以是固定值，也可以是规则占位符）

::: tip 为什么用"参数类型"而不是"模块"
模块是测试用例的概念，数据工厂要解决的是"我有哪些数据资产"，所以用参数类型 / 文件夹这种更纯粹的归类方式，方便跨模块复用同一份数据。
:::

## 界面布局

进入 **AI 功能 → 数据工厂**，左右分栏：

- **左侧：项目树** — 展示项目 / 参数类型 / 参数三级节点，点击切换右侧内容
- **右侧：参数卡片** — 选中某个参数类型后，以卡片网格展示该类型下的所有参数

![参数卡片网格](/screenshots/zh/data_factory.png)

### 参数卡片

每张卡片代表一个参数，展示参数名、值预览和来源规则，并提供快捷操作：

| 操作 | 说明 |
|------|------|
| **编辑** | 修改参数名、值或规则 |
| **删除** | 从当前参数类型下移除 |
| **复制值** | 把规则占位符复制到剪贴板，方便粘贴到用例 |

## 操作步骤

### 1. 新建项目与参数类型

1. 在左侧项目树点击「+ 新建项目」，输入项目名
2. 右键项目节点 → 「新建参数类型」（相当于建文件夹），例如"用户信息"、"订单数据"
3. 可在一个项目下建多个参数类型，按业务域分门别类

### 2. 添加参数

1. 选中参数类型节点 → 右侧点「+ 添加参数」
2. 填写：
   - **参数名**：如 `phone`、`orderNo`、`amount`
   - **参数值**：固定值或规则占位符（规则见下方）
3. 保存后卡片立即出现在网格中

### 3. 搜索与过滤

当参数数量变多时，用顶部的搜索框按参数名或值模糊过滤，定位到目标卡片。

### 4. 在用例中引用

在测试用例的请求参数里直接写规则占位符即可，例如：

```json
{
  "username": "${phone()}",
  "email": "${email()}",
  "idCard": "${id_card()}",
  "nickname": "user_${random_string(6)}"
}
```

执行引擎会扫描这些占位符，**每次执行实时生成**新值，不会复用上次跑过的数据。详见 [变量体系 - 动态生成规则](./variables.md#动态生成规则)。

## 内置随机规则

数据工厂内置以下规则占位符，覆盖绝大多数测试场景：

| 规则 | 含义 | 示例输出 |
|------|------|---------|
| `${phone()}` | 随机中国大陆手机号 | `13812345678` |
| `${email()}` | 随机邮箱 | `example@domain.com` |
| `${name()}` | 随机中文姓名 | `张伟` |
| `${id_card()}` | 随机身份证号（18 位） | `110101199001011234` |
| `${random_string(N)}` | 长度为 N 的随机字符串（字母 + 数字） | `aB3dE8fG` |
| `${random(N)}` | N 位随机整数（如 `random(5)` 生成 5 位数） | `42831` |
| `${random(a-b)}` | 区间 [a, b] 内的随机整数（旧语法，仍支持） | `42` |
| `${enum(男,女,未知)}` | 从枚举集合中随机取一个 | `女` |
| `${datetime(-7d,+0d,%Y-%m-%d)}` | 区间内的随机日期，按指定格式输出 | `2026-07-15` |
| `${timestamp()}` | 当前 Unix 时间戳（秒） | `1721460000` |

::: warning 规则占位符与变量占位符的区别
- 规则占位符**带括号**：`${phone()}`、`${random(8)}` — 由数据工厂实时生成
- 变量占位符**不带括号**：`${token}`、`${userId}` — 从全局 / 局部参数池取值

引擎通过"是否带括号"区分两者，因此规则占位符不会误伤同名变量。详见 [变量体系](./variables.md)。
:::

::: details Faker 未安装时的降级行为
随机规则依赖 Python `Faker` 库（中文 + 英文 locale）。若后端环境未安装 Faker，平台会自动降级：

- `phone()` 仍能用（内置手机号前缀池）
- `email()` / `name()` 用纯标准库拼一个近似值
- `id_card()` 用算法生成符合位数的伪身份证号
- `random_string()` / `random()` / `enum()` / `datetime()` 完全不依赖 Faker

建议在生产环境安装 Faker 以获得最真实的中文数据：`pip install Faker`。
:::

## 用例引用示例

下例是一个"注册新用户"的接口用例，关键参数全部用规则占位符，保证每次执行都是全新的注册数据：

```json
{
  "method": "POST",
  "path": "/api/user/register",
  "parameters": {
    "phone": "${phone()}",
    "email": "${email()}",
    "idCard": "${id_card()}",
    "password": "Pwd_${random_string(8)}",
    "nickname": "tester_${random(4)}",
    "gender": "${enum(男,女)}",
    "birthday": "${datetime(-30y,-18y,%Y-%m-%d)}"
  }
}
```

执行时，引擎依次生成每个字段的真实随机值，再用这些值发请求。断言返回的 `userId` 不为空即视为注册成功。

## 数据工厂填充到用例（一键替换）

除了在用例里**手写规则占位符** `${phone()}`，平台还提供一个反向入口：**在测试用例编辑页一键把数据工厂的值填充到用例 body**。

### 适用场景

- 数据工厂里存了一批**固定测试值**（如 `imei=11`、`batteryType=LFP`），用例 body 里手写太繁琐
- 多个用例共享同一组测试值，集中维护在数据工厂，改一处生效
- 想**批量替换**用例里同名字段，避免逐个改

### 操作步骤

1. 打开任意测试用例的**编辑页**
2. 在参数编辑区上方找到「**数据工厂参数填充**」按钮（蓝色）
3. 弹窗里按参数类型分组列出所有数据工厂参数，勾选要填充的项（支持顶部搜索框过滤）
4. 点「**一键智能替换**」—— 平台会**递归扫描用例 body 里的所有字段**（含数组、嵌套对象），把同名字段的值替换为数据工厂里的值

### 替换规则

| body 结构 | 行为 |
|---|---|
| `{imei: "old", name: "x"}` | `imei` 命中 → 替换为新值；`name` 不命中 → 保留 |
| `[{imei: "a"}, {imei: "b"}]` | **数组里每个元素的 `imei` 都被替换** |
| `{users: [{imei: "a"}, {imei: "b"}]}` | **嵌套结构里的同名字段也会被递归替换** |
| body 里**不存在**的字段 | **不会被新增**（数据工厂只替换已有字段，不擅自扩展 body 结构） |

::: tip 替换语义
「数据工厂填充」只覆盖 body 里**已存在**的同名字段，不会新增字段。这样设计是因为：
- 数据工厂的本职是「替换常用参数值」（如把所有用例的 `imei` 统一换成某个测试值）
- 用例里没有的字段，用户肯定有自己的设计意图，平台不该擅自补
- 如果想新增字段，请直接在用例 body 里手写

因此，"填充"和"智能替换"两个按钮**行为一致**，都只做覆盖式替换。
:::

### 兼容数组形式 body

很多业务接口的 POST body 是**顶层数组**（如批量操作接口 `[{"imei": "xxx"}, {"imei": "yyy"}]`）。平台的递归替换逻辑完整支持：

```json
// 原始 body（数组）
[
  { "imei": "OLD_1", "name": "张三" },
  { "imei": "OLD_2", "name": "李四" }
]

// 数据工厂里勾选 imei = 11，点智能替换后
[
  { "imei": "11", "name": "张三" },
  { "imei": "11", "name": "李四" }
]
```

每个数组元素的 `imei` 都会被替换，其他字段保留。

::: warning 历史问题：数组 body 替换失效
早期版本里「数据工厂填充」遇到数组 body 会静默失效 —— 表现是"勾选了参数、点了替换、提示成功，但 body 没变"。根因是替换逻辑把 body 当字典处理，往数组对象上塞命名属性，`JSON.stringify` 序列化时被丢弃。**已修复**，现在数组、嵌套对象都能正确递归替换。
:::

## 与全局参数、局部参数的分工

| 参数来源 | 用途 | 生命周期 | 适用场景 |
|---------|------|---------|---------|
| **全局参数** | Token、baseUrl 等环境信息 | 跨用例共享 | 所有用例都需要的环境常量 |
| **局部参数** | 临时覆盖全局参数 | 单用例内 | 个别用例需要换 Token / 调试值 |
| **数据工厂** | 动态生成的业务数据 | 每次执行即时生成 | 注册、下单等需要新鲜数据的场景 |

三者配合使用：全局参数负责"环境"，数据工厂负责"业务数据"，局部参数负责"覆盖"。

## 常见问题

::: warning 为什么规则占位符没被替换？
排查清单：

1. 占位符必须**严格匹配** `${func()}` 或 `${func(arg)}` 格式，括号、参数都不能少
2. 函数名必须在上表的内置规则列表里，自定义函数当前不支持
3. 字段值**整段**就是规则占位符时最稳定，混在长文本里要看后端是否启用数据工厂引擎
4. 后端日志若提示 `数据工厂引擎未启用`，说明 `data_factory_engine` 模块加载失败，联系运维检查依赖
:::

::: tip 想批量预览生成的数据？
数据工厂页面提供"预览"按钮，可输入数量 N 一次性预生成 N 行，用于肉眼校验规则正确性。预览不会污染实际执行结果。
:::
