# 操作日志

> 谁在什么时候改了什么——每一次写操作（新增 / 修改 / 删除）都自动记录，可追溯。

操作日志由后端中间件自动记录，**无需手动开启**。每次写操作（POST / PUT / DELETE / PATCH）都会记下：操作人、模块、动作、参数、IP、会话 ID 和时间。

入口：**接口自动化工作台 → 系统管理 → 操作日志**。

![操作日志](/screenshots/zh/operation_logs.png)

## 日志字段

| 列 | 含义 |
|----|------|
| 操作人 | 执行该操作的用户 |
| 操作类型 | 新增 / 修改 / 删除等 |
| 模块 | 测试用例、测试套件、Mock、AI 用例等业务模块 |
| 动作 | 具体动作描述 |
| 资源名称 | 被操作的对象名称 |
| IP 地址 | 操作来源 IP |
| 时间 | 操作发生时间 |

## 筛选与查询

- **快捷时间**：下拉选择常用时间范围（今天 / 最近一周等），也可自定义起止时间
- **条件筛选**：按操作人、操作类型、模块组合过滤
- **分页浏览**：默认每页 10 条，可翻页

## 权限与可见范围

| 角色 | 可见范围 |
|------|----------|
| 普通用户 | 只能看到**自己**的操作日志 |
| 超级管理员 | 可看到**全员**的操作日志 |

::: tip 与监控中心的关系
超管在[监控中心](../guide/admin-monitor.md)里能基于这些日志做更深的全局分析：按用户聚合的操作时间线、资源生命周期、登录会话分组。操作日志页适合精确查询某条记录，监控中心适合看全局趋势。
:::
