# 测试用例

**路径**：左侧导航 → 测试管理 → 测试用例

测试用例是接口测试平台的**核心操作页面**，几乎所有日常操作都在这里完成：创建用例、配置参数、写断言、设置变量提取、编排依赖、复制 / 排序 / 启用禁用。本页把用例编辑页的全部能力讲清楚，重点说明**变量提取**和**依赖编排**这两个高级能力。

![测试用例](/screenshots/zh/test_cases.png)

## 页面布局

测试用例页采用**左侧项目树 + 右侧用例表格**的双栏布局：

- **左侧项目树**：项目 → 模块 → 用例的三层结构，支持展开 / 折叠 / 搜索
- **右侧用例表格**：当前选中模块下的用例列表，支持排序、批量操作、新建 / 编辑

## 创建用例

### 三种创建方式

| 方式 | 适用场景 |
|------|---------|
| **手动新建** | Swagger 没覆盖的接口、临时调试 |
| **Swagger 导入** | 批量生成，最常用，见 [Swagger 解析](./swagger.md) |
| **JMeter 转换** | 从已有 JMeter 脚本迁移 |
| **复制已有用例** | 基于相似用例快速派生异常用例 |

### 字段说明

新建 / 编辑用例时需要填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| 用例名称 | 清晰描述测试目的 | `登录-正常`、`下单-库存不足` |
| 请求路径 | 接口 URL 路径 | `/api/user/login` |
| 请求方法 | GET / POST / PUT / PATCH / DELETE / **WebSocket** | `POST` |
| 请求参数 | JSON 格式 | `{"username":"admin","password":"123456"}` |
| 请求头 | 键值对 | `Content-Type: application/json` |
| 期望值 | 断言表达式，见下方 | `code=200 and field:code=0` |
| 局部参数 | 单用例专属参数 | 见 [局部参数](./local-params.md) |

## 断言表达式

期望值字段支持以下断言写法，多个条件用 `or` / `and` 连接：

| 写法 | 含义 | 例子 |
|------|------|------|
| `code=200` | HTTP 状态码等于 200 | `code=200` |
| `code!=500` | 状态码不等于 500 | `code!=500` |
| `status=101` | WebSocket 握手成功 | `status=101` |
| `contains:xxx` | 响应体包含某文本 | `contains:success` |
| `field:msg=ok` | JSON 字段等于某值 | `field:code=0` |

**组合断言示例：**

```text
code=200 and field:code=0 and contains:token
```

表示：HTTP 200 且响应 JSON 的 `code` 字段为 0 且响应体包含 `token`。

::: tip 断言写在哪
断言写在「期望值」字段。如果某条用例不配期望值，平台只发请求不判断结果，永远算「通过」——这通常不是你想要的，建议每条用例都写断言。
:::

## 变量提取（核心能力）

变量提取是从响应中抓取数据、供后续用例使用的机制。最典型的场景：**登录后提取 token，注入到后续业务请求**。

### 配置方式

在用例编辑页的「变量提取」区域：

| 字段 | 说明 | 示例 |
|------|------|------|
| 变量名 | 提取后保存的变量名 | `token` |
| 提取路径 | JSON Path 或文本匹配规则 | `$.data.token` |

执行时，平台从响应 JSON 中按路径取出值，存入变量 `token`，本批次后续用例可用 `${token}` 引用。

### 示例：登录后提取 token

**登录用例响应：**

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "userId": 1001
  }
}
```

**变量提取配置：**

| 变量名 | 提取路径 |
|--------|---------|
| `token` | `$.data.token` |
| `userId` | `$.data.userId` |

**后续业务用例的请求头：**

```text
Authorization: Bearer ${token}
X-User-Id: ${userId}
```

执行时，后续用例的请求会自动注入真实 token 与 userId，完成完整的业务链路测试。

::: details 变量提取与全局参数的区别
- **全局参数**：执行前手动配置的固定值（如固定 Token）
- **变量提取**：执行中从响应动态抓取的值（如登录返回的临时 Token）
两者都用 `${...}` 引用，执行时变量提取的值优先级更高。
:::

## 依赖编排

复杂业务流程（如电商下单）需要多个用例按顺序执行并传递数据。平台提供两种依赖配置：

### 前置 / 后置用例

在用例编辑页设置：

- **前置用例**：本用例执行前先执行的用例（通常是登录、数据准备）
- **后置用例**：本用例执行后接着执行的用例（通常是清理、删除）

配合变量提取，前置用例提取的变量自动传给后续用例。

### AI 自动编排（推荐）

用 [流程编排](../advanced/flow-orchestration.md) 让 AI 分析接口语义自动推断依赖：

1. 选择多个相关用例（如 登录 / 查询 / 修改 / 删除）
2. AI 根据接口路径与参数自动判断执行顺序
3. 自动配置变量提取与注入
4. 确认编排结果后应用

这比手动配前置 / 后置高效得多，尤其适合接口众多的复杂业务。

## 用例管理操作

### 复制

基于已有用例派生新用例，避免重复填写。常用于：从正常用例派生异常用例、从 GET 用例派生 PUT 用例。

### 排序

模块内用例支持拖拽排序，调整执行顺序。执行测试时，同一模块内的用例按列表顺序执行。

### 启用 / 禁用

每条用例都有启用开关。禁用后的用例不参与执行（不删除），适合：

- 临时下线不稳定用例
- 调试期间只跑核心用例
- 保留历史用例但不参与回归

支持批量启用 / 禁用。

### 导入 / 导出 Excel

用例支持 Excel 批量导入导出，适合：

- 批量迁移（从其他系统搬到本平台）
- 离线编辑（在 Excel 里批量改后导回）
- 团队协作（把用例库发给外部评审）

### 调试执行

单独运行一个用例，立即看请求 / 响应 / 断言结果，不生成报告，用于快速排查。

## WebSocket 用例

平台支持 WebSocket 接口测试。在请求方法下拉框选择最后一项 **WebSocket**，会出现 WS 提示面板。

### 两种场景

| 场景 | 操作 | 参数示例 | 断言 |
|------|------|---------|------|
| **连接测试**（仅握手） | method=WS，parameters 留空或 `{}` | `{}` | `status=101`（握手成功） |
| **单发单收** | 填 `message` 字段 | `{"message":"hello"}` | `contains:期望回复内容` |

### URL 自动转换

平台自动把 HTTP 协议转成 WS 协议：

- `http://` → `ws://`
- `https://` → `wss://`

::: warning WS 排查
连接失败时状态码为 0，`error` 字段含连接错误信息。先用「连接测试」场景（不填 message）验证握手是否通，握手成功后再加 message 做单发单收。断言用 `contains:` 匹配非 JSON 回复。
:::

## 配置示例：完整的登录-下单链路

| 用例 | 方法 | 路径 | 参数 | 期望值 | 变量提取 |
|------|------|------|------|--------|---------|
| 登录 | POST | `/api/login` | `{"user":"a","pwd":"b"}` | `field:code=0` | `token ← $.data.token` |
| 查商品 | GET | `/api/product/100` | — | `code=200` | `price ← $.data.price` |
| 下单 | POST | `/api/order` | `{"productId":100,"price":"${price}"}` | `field:code=0` | `orderId ← $.data.orderId` |
| 取消订单 | POST | `/api/order/cancel` | `{"orderId":"${orderId}"}` | `field:code=0` | — |

请求头统一配：`Authorization: Bearer ${token}`（全局或局部参数）。

## 常见问题

### 用例执行失败怎么排查

1. 用「调试执行」单独跑，查看完整请求 / 响应
2. 检查请求路径、参数格式、请求头
3. 确认 `${...}` 引用的变量是否已定义（全局参数 / 上游提取）
4. 确认期望值断言是否过严（如 `field:code=0` 但接口返回的是字符串 `"0"`）

### 变量提取没拿到值

- 确认提取路径与响应 JSON 结构匹配（用调试执行看实际响应）
- 确认前置用例已执行成功（前置失败则后续用例拿不到变量）
- JSON Path 区分大小写，字段名必须完全一致

### WebSocket 连接失败

见上方 [WebSocket 用例](#websocket-用例) 的排查建议。
