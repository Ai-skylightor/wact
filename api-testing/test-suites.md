# 测试套件

**路径**：左侧导航 → 执行与结果 → 测试套件

测试套件把多个测试用例打包成一个**可复用单元**。当用例数量上来后（几十上百条），每次执行都手动勾选太繁琐；套件让你「一键选一组」，把回归用例、核心链路用例、P0 用例分别组织起来，长期复用。

![测试套件](/screenshots/zh/test_suites.png)

## 为什么需要套件

没有套件时，要跑「核心回归」，你需要在执行测试页手动勾选 30 个用例。有了套件：

- **执行页一键选择**：执行测试时直接选套件，不用逐条勾选
- **CI/CD 定时任务引用**：定时任务以套件为单位配置
- **团队共享执行口径**：所有人对「核心回归」跑的是同一批用例，结果可对比

## 创建套件

### 操作步骤

1. 进入测试套件页，点击「新建套件」
2. 填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| 套件名称 | 清晰描述套件用途 | `核心回归`、`P0 冒烟`、`订单全链路` |
| 描述 | 套件包含的范围与目的 | `每次发版必跑的核心接口集合` |
| 项目 | 套件归属的项目 | `电商前台` |
| **用例执行模式** 🆕 | 套件内**接口用例之间**的执行方式（见下节） | `串行（默认）` / `并行` |
| **请求超时** 🆕 | 每个接口请求的超时秒数（默认 20s） | `20`、`60` |

3. 保存

## 用例执行模式：串行 / 并行 🆕

创建套件时可以选择套件内**接口用例之间**的执行方式：

![创建测试套件-用例执行模式](/screenshots/zh/test_suites_create.png)

| 模式 | 行为 | 适合场景 |
|------|------|---------|
| 🐢 **串行（默认）** | 用例按顺序执行，一个跑完再跑下一个 | 有依赖关系的链路（登录→下单→支付）、前置用例的结果要给后续用例用 |
| 🐰 **并行** | 用例之间并发执行 | 用例间相互独立、追求最快出结果 |

::: tip 什么时候该选串行？
当套件里的用例**有依赖关系**时务必选串行。例如「登录」用例提取的 token 要注入到后续「查询订单」「修改资料」用例里，必须等登录跑完拿到 token 后，后续用例才能正确执行。并行模式下用例同时跑，token 还没提取出来就被引用，会导致后续用例失败。
:::

::: warning 这个模式只针对接口用例
「用例执行模式」控制的是**同一个套件内接口用例之间**的执行方式。它和「执行测试」页的[模块间串行/并行](./execution.md)是不同层级的控制：
- **执行测试页** → 控制**模块之间**
- **测试套件** → 控制**套件内用例之间**
- **CI 回归测试集** → 控制[套件之间](../integration/regression.md)
:::

### 添加用例

1. 进入套件详情
2. 点击「添加用例」
3. 从用例列表中勾选要加入的用例（支持跨模块选择）
4. 确认添加

::: tip 一个用例可以属于多个套件
用例与套件是多对多关系。「登录」用例可以同时属于「核心回归」和「P0 冒烟」两个套件，互不影响。修改用例后，所有引用它的套件自动同步。
:::

## 套件管理

| 操作 | 说明 |
|------|------|
| 编辑 | 修改套件名称、描述、用例清单 |
| 复制 | 基于已有套件快速派生（如从「核心回归」复制出「核心回归-预发」） |
| 删除 | 删除套件本身，**不影响**用例 |
| 启用 / 禁用 | 暂停使用，不删除 |

## 执行套件

### 在执行测试页

详见 [执行测试](./execution.md)：

1. 进入执行测试页
2. 选择项目
3. 在选择用例时，切换到「按套件」选择
4. 勾选目标套件 → 套件内所有用例自动加载
5. 配置 baseUrl 与 Mock 选项 → 执行

### 在 CI/CD 定时任务中

详见 [CI/CD 定时任务](../integration/ci-cd.md)：

1. 新建定时任务
2. 关联一个测试套件
3. 配置 Cron 表达式与通知方式
4. 定时器到点自动执行套件

## 配置示例

### 示例 1：P0 冒烟套件

发版前必跑的最小集合，覆盖最核心的接口：

| 套件名 | 包含用例 | 用途 |
|--------|---------|------|
| `P0 冒烟` | 登录、首页、核心查询、下单 | 发版前 10 分钟快速验证 |

### 示例 2：核心回归套件

每次发版后跑的完整回归集：

| 套件名 | 包含用例 | 用途 |
|--------|---------|------|
| `核心回归` | P0 冒 smoke 全部 + 订单流程 + 支付流程 + 用户管理 | 每日定时跑 |

### 示例 3：业务全链路套件

按业务流程而非模块组织，验证完整链路：

| 套件名 | 包含用例 | 用途 |
|--------|---------|------|
| `下单全链路` | 登录 → 浏览 → 加购 → 下单 → 支付 → 评价 | 跨模块业务验证 |

这类套件的用例间通常有依赖关系，建议配合 [流程编排](../advanced/flow-orchestration.md) 自动编排执行顺序。

## 套件与模块的关系

| 维度 | 模块 | 套件 |
|------|------|------|
| 组织维度 | 按接口归属（技术分类） | 按使用场景（业务分类） |
| 一个用例属于 | 仅一个模块 | 可属于多个套件 |
| 主要用途 | 用例的「家」 | 用例的「工作编组」 |

同一个用例库，可以按业务模块（用户、订单、支付）归类管理，同时按使用场景（冒烟、回归、P0）组成不同套件。两者互补，不冲突。

## 常见问题

### 套件里的用例修改了，套件需要更新吗

不需要。套件引用的是用例本身，用例内容修改后，套件执行时自动用最新版本。

### 删除套件里的用例会发生什么

被删的用例会自动从所有引用它的套件中移除，不影响套件本身。

### 套件能跨项目吗

不能。套件归属单个项目，只能添加该项目下的用例。跨项目的执行需要分多次跑。

### 套件执行顺序

套件的「用例执行模式」选**串行**时，默认按套件内用例的添加顺序执行。需要特定顺序时（如登录在前），在添加用例时注意顺序，或用 [流程编排](../advanced/flow-orchestration.md) 编排。选**并行**时则不分先后，同时执行。
