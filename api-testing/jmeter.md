# JMeter 解析

**路径**：左侧导航 → 数据准备 → JMeter 解析

如果团队之前用 JMeter 做接口测试或压测，这些 `.jmx` 脚本不需要丢弃。平台提供两条路径：把脚本转换成平台原生的测试用例长期维护，或直接在平台上执行原始脚本，保留 JMeter 的全部能力。

![JMeter 解析](/screenshots/zh/jmeter.png)

## 两个 Tab

JMeter 解析页提供两个独立的功能 Tab：

| Tab | 用途 |
|-----|------|
| **上传文件** | 上传 `.jmx` 文件到平台，管理已上传文件列表 |
| **直接执行** | 从已上传文件中选择并执行脚本，支持传入自定义属性 |

## 上传文件

### 操作步骤

1. 切换到「上传文件」Tab
2. 点击上传区域或拖拽 `.jmx` 文件
3. 上传完成后，文件出现在已上传列表中
4. 列表展示：文件名、上传时间、文件大小、操作（执行 / 删除）

### 文件管理建议

- 文件名建议带版本或日期：`order-flow-v2-20260701.jmx`，避免后续混淆
- 不再使用的脚本及时删除，避免列表过长
- 同一脚本多次迭代时，建议保留历史版本以便回溯

## 直接执行

「直接执行」Tab 用于调用 JMeter 引擎执行原始脚本，**不经过平台的测试用例转换**，保留 JMeter 的全部特性（线程组、定时器、监听器、断言等）。

### 操作步骤

1. 切换到「直接执行」Tab
2. 从下拉框选择已上传的 `.jmx` 文件
3. 可选：填写自定义属性（JSON 格式，对应 JMeter 的 `-J` 参数）
4. 点击「执行」

### 自定义属性

通过 JSON 传入运行时参数，等价于命令行的 `-J` 选项：

```json
{
  "host": "test.example.com",
  "port": "8080",
  "threads": "10",
  "loop": "100"
}
```

脚本中通过 `${__P(host)}`、`${__P(threads)}` 等方式引用。这样同一份脚本可以跑不同环境、不同并发，无需修改 `.jmx` 文件。

## 两种路径如何选择

| 场景 | 建议路径 | 理由 |
|------|---------|------|
| 想长期在平台维护用例、配合 CI/CD | 转换成平台用例 | 用例、参数、报告统一管理，可与其他模块用例混编执行 |
| 需要保留 JMeter 高级特性（线程组、定时器） | 直接执行 | 平台用例是单线程顺序执行，不适合复杂压测场景 |
| 老脚本一次性回归验证 | 直接执行 | 无需转换成本，跑完看结果即可 |
| 想接入平台的 AI 编排、Mock、变量提取 | 转换成平台用例 | 这些能力只在平台原生用例上生效 |

::: warning 前置依赖
「直接执行」需要服务器安装 JMeter 5.x 并配置 `JMETER_HOME` 环境变量。未安装时执行会报错。安装方法参考 JMeter 官方文档。
:::

## 配置示例：跨环境回归

同一份登录脚本，在测试环境与预发环境各跑一次：

```json
// 第一次执行：测试环境
{ "env": "test", "host": "10.0.0.10", "token": "test-token" }

// 第二次执行：预发环境
{ "env": "staging", "host": "10.0.0.11", "token": "staging-token" }
```

脚本里通过 `${__P(env)}`、`${__P(host)}` 引用，两份环境共用一份脚本，避免重复维护。

## 常见问题

### 执行报错：找不到 jmeter 命令

服务器未安装 JMeter 或未配置环境变量。检查方式：

```bash
echo $JMETER_HOME
which jmeter
```

二者都为空则需要安装并配置。

### 上传文件大小限制

默认上传限制取决于平台与反向代理（Nginx `client_max_body_size`）。超大 `.jmx` 文件建议先在本地瘦身（删除冗余监听器结果），再上传。

### 转换成用例后参数丢失

JMeter 脚本中的用户变量、CSV 数据文件、前置处理器等高级特性，在转换为平台用例时**不会完全等价映射**。转换后请逐一检查用例参数，必要时用 [全局参数](./global-params.md) 补齐。
