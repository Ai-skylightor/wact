# 局部参数

**路径**：测试用例编辑页内的局部参数区

局部参数是绑定到**单个测试用例**的参数，作用范围只在该用例内部。它最典型的两个用途是：覆盖同名全局参数做差异化测试，以及为异常场景用例准备专属的输入数据。

![局部参数](/screenshots/zh/local_params.png)

## 与全局参数的区别

| 维度 | 全局参数 | 局部参数 |
|------|---------|---------|
| 作用范围 | 所有用例自动注入 | 仅绑定到的单个用例 |
| 配置位置 | 测试管理 → 全局参数 | 测试用例编辑页内 |
| 典型用途 | Token、baseUrl、租户头 | 临时覆盖、异常输入、特殊业务数据 |
| 优先级 | 低 | 高（覆盖同名全局参数） |

## 优先级规则

平台按以下优先级取值（高 → 低）：

```text
局部参数  >  全局参数  >  用例内联参数
```

当局部参数与全局参数同名时，**局部参数胜出**。这个机制让你能在不修改全局参数的前提下，给单个用例换一个值。

## 操作步骤

1. 在 [测试用例](./test-cases.md) 页打开某个用例的编辑页
2. 找到「局部参数」区域
3. 新建参数：

| 字段 | 说明 |
|------|------|
| 参数名 | 与全局参数同名则覆盖；不同名则新增 |
| 值 | 该用例专用的值 |
| 优先级 | 数值越大越优先（用于多个局部参数冲突时） |

4. 保存用例

::: tip 引用方式不变
无论参数来自全局还是局部，在用例的请求头、URL、请求体里都用 `${参数名}` 引用，写法完全一致。
:::

## 三个典型用法

### 用法 1：临时覆盖全局参数（调试）

全局参数 `Authorization` 配的是测试账号 A 的 Token。某个用例想用账号 B 测试越权场景：

| 参数名 | 值 | 说明 |
|--------|-----|------|
| `Authorization` | `Bearer <accountB_token>` | 仅本用例用账号 B，其他用例仍用 A |

不用改全局参数，不影响其他用例。

### 用法 2：异常场景的专属输入

一条「手机号格式错误」的异常用例，需要传入一个非法手机号：

| 参数名 | 值 |
|--------|-----|
| `phone` | `123`（格式非法） |

正常用例的 `phone` 来自 [数据工厂](../advanced/data-factory.md) 或固定值，异常用例用局部参数注入非法值。

### 用法 3：业务专属数据

下单用例需要一个特殊的商品 ID（如秒杀商品），这个 ID 其他用例不用：

| 参数名 | 值 |
|--------|-----|
| `product_id` | `SKU_FLASH_001` |

## 异常场景模板参数

写异常用例时，局部参数是承载「异常输入」的地方。下表列出常见的异常模板：

| 异常类型 | 参数名 | 值 | 验证点 |
|---------|--------|-----|--------|
| 必填缺失 | `phone` | （空字符串） | 返回参数校验错误 |
| 格式错误 | `email` | `not-an-email` | 返回格式校验错误 |
| 类型混淆 | `age` | `"abc"`（字符串） | 返回类型错误 |
| 超长字符串 | `name` | 1000 字符 | 返回长度超限或正常处理 |
| SQL 注入 | `username` | `' OR 1=1 --` | 不返回敏感数据 |
| XSS | `remark` | `<script>alert(1)</script>` | 转义后存储 |
| 边界值 | `amount` | `0` / `-1` / `99999999` | 业务边界处理 |

::: tip 配合 AI 生成
不必手动一条条写异常参数。在测试用例页选中正常用例，用 [AI 生成异常场景](../ai/exception-cases.md)，AI 会基于接口定义自动生成一组覆盖上述场景的异常用例。
:::

## 配置示例：登录异常用例

正常登录用例（密码 `123456`）已经有了，现在要写一条「密码错误」的异常用例：

1. 复制正常用例，改名为 `登录-密码错误`
2. 在新用例的局部参数里：

| 参数名 | 值 |
|--------|-----|
| `password` | `wrong_password` |

3. 修改期望值断言：`field:code=1001`（假设 1001 是密码错误码）

这样无需新增请求体字段，平台在执行时把 `password` 替换为 `wrong_password` 发出请求。

## 常见问题

### 局部参数会影响其他用例吗

不会。局部参数严格绑定到单个用例，其他用例完全无感知。

### 删除用例后局部参数去哪了

删除用例时，其绑定的局部参数一起删除，不会成为孤儿数据。

### 同名局部参数之间的优先级

同一用例内配了多个同名局部参数时（极少见），按 `优先级` 数值大的胜出。一般避免同名重复配置。

### 局部参数能引用全局参数吗

可以。局部参数的「值」字段里也可以用 `${other_global}`，平台会先解析全局参数再赋给局部参数。适合做参数组合：`base_url + path`。
