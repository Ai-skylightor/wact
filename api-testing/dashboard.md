# 仪表盘

**路径**：左侧导航 → 概览 → 仪表盘

仪表盘是登录后进入的默认页面，用一组统计卡片和快速开始引导，让你在 3 秒内掌握平台当前状态并找到下一步该做什么。

![仪表盘](/screenshots/zh/dashboard.png)

## 统计卡片

页面顶部展示四张全局统计卡片：

| 卡片 | 含义 | 数据来源 |
|------|------|---------|
| **测试用例数** | 平台所有用例总量（含禁用） | 测试用例表 |
| **测试套件数** | 已创建的测试套件数量 | 测试套件表 |
| **报告数** | 历史执行产生的报告总量 | 测试报告表 |
| **通过率** | 最近一次执行批次的整体通过率 | 最近一次执行记录 |

::: tip 通过率怎么看
通过率反映的是**最近一次执行**的结果，不是历史平均。如果最近一次执行只跑了少量用例，通过率只代表这批，不代表全量用例的健康度。要看全量，请到 [执行测试](./execution.md) 页手动跑一次全量回归。
:::

## 快速开始引导

统计卡片下方是「快速开始」四步引导，对应平台的主流程：

1. **Swagger 导入** → 跳转到 [Swagger 解析](./swagger.md)
2. **生成用例** → 跳转到 [测试用例](./test-cases.md)
3. **配置参数** → 跳转到 [全局参数](./global-params.md)
4. **执行测试** → 跳转到 [执行测试](./execution.md)

每一步都带有跳转链接，第一次使用平台时按顺序点一遍就能跑通完整流程。

## 常见用法

### 场景 1：每天到岗先看通过率

如果你配置了夜间回归任务，到岗后第一件事是看仪表盘的通过率卡片：通过率掉下来了 → 点「报告数」进入 [测试报告](./reports.md) 查看失败详情。

### 场景 2：评估团队测试资产沉淀

通过用例数和套件数判断团队测试资产的覆盖度。如果数字长期不增长，可能意味着新接口没有被纳入自动化，需要推动开发同步提交 Swagger。

### 场景 3：新手引导

新成员加入时，把仪表盘作为入口页，让他按四步引导熟悉平台，比单独讲解功能模块更高效。
