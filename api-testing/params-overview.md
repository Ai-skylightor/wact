# 接口参数总览

**路径**：左侧导航 → 测试管理 → 接口参数总览

接口参数总览是一张**只读**的参数大表：把所有从 Swagger 解析进来的接口参数集中展示，方便快速查询每个接口有哪些参数、什么类型、是否必填。它不直接参与执行，而是配置用例和参数时的查询入口。

![接口参数总览](/screenshots/zh/params_overview.png)

## 解决什么问题

没有这张表时，要知道「`/api/order/create` 接口有哪些必填参数」，你需要：

1. 翻 Swagger 文档找接口
2. 或在测试用例页找到对应用例
3. 进编辑页查看参数

参数总览把所有接口的参数扁平化展示，搜索一次即可定位，特别适合在以下场景：

- 写新用例前确认参数清单
- 排查失败用例时核对参数类型与必填项
- 评估接口变更影响（参数是否新增 / 删除）

## 页面布局

| 区域 | 内容 |
|------|------|
| 顶部过滤 | 关键字搜索框、请求方法筛选（GET / POST / PUT / DELETE 等） |
| 参数表格 | 每行一个参数，列出所属接口、参数名、类型、位置、是否必填、枚举值 |
| 批量操作 | 全选、批量删除 |

### 表格字段

| 列 | 含义 |
|----|------|
| **接口路径** | 参数所属的接口，如 `/api/user/login` |
| **方法** | 接口的 HTTP 方法 |
| **参数名** | 参数键名，如 `username` |
| **类型** | string / integer / boolean / object 等 |
| **位置** | header / query / body / path |
| **必填** | 是 / 否 |
| **枚举值** | 如果参数有枚举约束，列出可选值 |

## 操作步骤

### 查找特定接口的参数

1. 在搜索框输入接口路径关键字，如 `order`
2. 列表实时过滤，显示所有含 `order` 的接口参数
3. 按 `方法` 进一步筛选（如只看 POST）

### 查找某类参数

想找出所有接口里名为 `pageSize` 的参数，直接在搜索框输入 `pageSize`，会跨所有接口展示这个参数的定义，方便发现命名不一致问题。

### 批量删除无用参数

接口下线后，对应参数仍残留在表中：

1. 搜索下线接口路径
2. 全选 → 批量删除

::: warning 删除影响
删除参数总览中的记录**不会**自动同步到已生成的测试用例。如果用例里仍引用了被删参数，执行时会按用例自身的参数发送请求。这里更多是数据清理与查询视图。
:::

## 常见用法

### 场景 1：写新用例前确认参数清单

写一条下单接口的异常用例（缺少必填字段），先在参数总览搜 `/api/order/create`，把所有必填字段记下来，再去 [测试用例](./test-cases.md) 页故意缺一个字段。

### 场景 2：核对接口变更

后端修改了接口（新增字段 / 改类型），重新 [Swagger 解析](./swagger.md) 后，在参数总览页对比新旧参数差异，判断是否需要调整现有用例。

### 场景 3：发现命名规范问题

搜索 `userId` / `user_id` / `uid`，看不同接口是否使用了不同命名。命名混乱是接口治理的常见信号，可以作为接口规范的反馈项给到后端团队。

## 常见问题

### 数据来源

参数总览的所有数据来自 [Swagger 解析](./swagger.md)。手动创建的用例中的参数**不会**出现在这里，只有解析时沉淀下来的接口定义才展示。

### 为什么有些接口没有参数

Swagger 文档中 `parameters` 和 `requestBody` 都没定义的接口，参数表里就不会有记录。这类接口多为 GET 无参查询，或 POST 体在文档里未声明。

### 搜索匹配规则

搜索是**大小写不敏感**的模糊匹配，匹配范围包括接口路径、方法、参数名。如果想精确匹配，把整段路径或参数名完整输入即可。
