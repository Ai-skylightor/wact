# 全局参数

**路径**：左侧导航 → 测试管理 → 全局参数

全局参数是**所有测试用例自动注入**的公共参数，主要用于避免在每个用例里重复配置 Token、租户 ID、环境地址等公共字段。配置一次，全平台用例自动引用；改一处，所有用例同步生效。

![全局参数](/screenshots/zh/global_params.png)

## 什么时候用全局参数

满足以下任一条件就适合放在全局参数：

- **几乎所有用例都要带**：鉴权 Token、Content-Type、租户头
- **按环境切换值**：测试 / 预发 / 生产三套 baseUrl、三套账号
- **希望集中管控**：Token 过期了改一处，而不是改 50 个用例

反之，如果某个参数只被 1-2 个用例使用，或属于业务输入数据（订单 ID、商品 ID），应该放在 [局部参数](./local-params.md) 或用例参数里。

## 参数位置

全局参数支持三种位置，覆盖 HTTP 请求的所有注入点：

| 位置 | 注入到 | 典型用途 |
|------|--------|---------|
| **header** | 请求头 | `Authorization`、`Content-Type`、`X-Tenant-Id` |
| **query** | URL 查询参数 | `appId`、公共版本号 |
| **body** | 请求体字段 | 公共业务字段 |

## 操作步骤

### 新建参数

1. 点击「新建参数」
2. 填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| 参数名 | 参数键名 | `Authorization` |
| 值 | 参数值 | `Bearer eyJhbGciOi...` |
| 类型 | 数据类型 | string |
| 位置 | header / query / body | header |
| 作用域 | global（全局）或 environment（按环境） | global |

3. 保存

### 按环境隔离

切换作用域为 `environment` 时，需要指定环境标签：

| 参数名 | 值 | 环境 |
|--------|-----|------|
| `base_url` | `http://test.example.com` | test |
| `base_url` | `http://staging.example.com` | staging |
| `base_url` | `https://api.prod.com` | prod |

执行测试时选择对应环境，平台只注入该环境的参数值。

### 启用 / 禁用

每条参数都有启用开关。禁用后该参数不再注入，但不删除记录，适合临时排查问题。

## 变量引用语法

全局参数配置后，在用例的请求头、参数、URL 中可以用 `${参数名}` 引用：

| 场景 | 写法 |
|------|------|
| 请求头 | `Authorization: ${auth_token}` |
| URL | `${base_url}/api/user/login` |
| 请求体 | `{"tenant": "${tenant_id}", "appId": "${app_id}"}` |

平台执行用例时会把 `${...}` 替换为对应的全局参数值。未定义的变量保留原样，便于排查。

::: tip 类型转换
需要数值类型时用 `${int(var)}` 转换，例如 `${int(pageSize)}` 把字符串 `20` 转成整数 20。详见 [变量体系](../guide/concepts.md#变量体系概述)。
:::

## 优先级规则

同一变量名在多个地方定义时，平台按以下优先级取值（高 → 低）：

```text
用例局部参数  >  全局参数  >  用例内联参数
```

即 [局部参数](./local-params.md) 可以覆盖同名全局参数。这条规则让你能在不影响其他用例的前提下，临时给某个用例换一个不同的值（如调试时换个测试账号）。

## 配置示例

### 示例 1：统一鉴权

| 参数名 | 值 | 位置 | 作用域 |
|--------|-----|------|--------|
| `Authorization` | `Bearer eyJhbGciOi...` | header | global |

所有用例的请求头自动带上 Token。Token 过期后改这一处即可。

### 示例 2：多环境 baseUrl

| 参数名 | 值 | 位置 | 环境 |
|--------|-----|------|------|
| `base_url` | `http://test.example.com` | query | test |
| `base_url` | `http://staging.example.com` | query | staging |
| `base_url` | `https://api.prod.com` | query | prod |

用例 URL 写成 `${base_url}/api/login`，执行时选环境即可切换目标。

### 示例 3：多租户头

| 参数名 | 值 | 位置 | 作用域 |
|--------|-----|------|--------|
| `X-Tenant-Id` | `tenant_001` | header | global |

所有请求自动带租户头，配合多租户 SaaS 系统测试。

## 常见问题

### 改了全局参数，已有报告会变吗

不会。报告是执行时生成的快照，记录的是当时的请求内容。改全局参数只影响**后续**执行。

### 全局参数会写入用例编辑页吗

全局参数独立存储，不会同步到用例编辑页的「请求头」「请求参数」字段。执行时平台在底层合并注入，用例本身看不到这些字段。如果想在用例里看到，可以改用 `${参数名}` 显式引用。

### 环境之间参数同步

环境之间参数**不会**自动同步。新增一个 `prod` 环境的 `base_url` 后，如果 `Authorization` 也需要按环境区分，要手动为每个环境分别配置。
