# Mock 服务

**路径**：左侧导航 → Mock 服务 → Mock 管理

Mock 服务用于在真实接口未就绪、或需要模拟异常场景时，按预定义规则返回数据。它解决了两个常见痛点：前后端并行开发时前端不被后端阻塞，以及测试异常场景时不需要真去制造异常。

![Mock 服务](/screenshots/zh/mock.png)

## 什么时候用 Mock

- **后端接口未完成**：前端先按 Mock 数据开发联调，后端就绪后切换
- **异常场景测试**：模拟超时、500、403、字段缺失等，验证系统容错
- **隔离第三方依赖**：测试支付时不真调第三方，避免污染真实订单
- **性能稳定的对照基线**：Mock 返回固定数据，便于排查前端问题是否由后端数据引起

## 规则配置

### 操作步骤

1. 创建 / 选择项目
2. 点击「新建规则」
3. 填写以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| **匹配 URL** | 要拦截的接口路径 | `/api/user/login` |
| **请求方法** | HTTP 方法 | `POST` |
| **响应状态码** | 返回的 HTTP 状态码 | `200` / `400` / `500` |
| **响应体** | JSON 格式的返回内容 | `{"code":0,"msg":"ok"}` |
| **响应延迟** | 模拟网络 / 处理耗时（毫秒） | `500`（模拟弱网） |

4. 可选：启用「动态响应」（用 Python 脚本生成动态数据）
5. 点击「测试 Mock」发送请求验证规则是否生效

### 匹配规则

请求到来时，平台按 **URL + 方法** 匹配：

- 命中规则 → 返回你配置的响应体与状态码
- 未命中 → 正常转发到真实接口，不影响业务

::: tip 匹配优先级
Mock 优先于真实接口。如果想临时禁用某条规则，直接在规则列表里停用它，无需删除。
:::

## 动态响应

静态响应体在每次请求都返回相同数据，无法覆盖需要变化的场景（如 ID 递增、时间戳、随机用户）。开启「动态响应」后，平台用 Python Faker 脚本实时生成响应：

```python
# 动态响应脚本示例：返回随机用户
import faker
fake = faker.Faker('zh_CN')

result = {
    "code": 0,
    "data": {
        "id": fake.random_int(min=1, max=10000),
        "name": fake.name(),
        "phone": fake.phone_number(),
        "email": fake.email(),
        "register_time": fake.date_time_this_year().isoformat()
    }
}
```

每次请求都会得到一个结构相同、内容不同的响应，适合前端列表页、详情页联调。

::: details 不想自己写脚本？
平台提供「AI 生成 Mock 规则」和「动态脚本生成」两个 AI 能力，见下方 [AI 能力](#ai-能力)。
:::

## AI 能力

Mock 服务深度集成了 AI，覆盖三个高频场景：

### 1. AI 生成 Mock 规则

输入一段自然语言描述，AI 自动生成完整的 Mock 规则（URL、方法、响应体）：

```
输入：模拟一个用户登录接口，成功时返回 token 和用户信息
AI 输出：
  URL: /api/user/login
  方法: POST
  状态码: 200
  响应体: {
    "code": 0,
    "msg": "success",
    "data": {
      "token": "eyJhbGciOiJIUzI1NiJ9...",
      "user": { "id": 1001, "name": "张三", "role": "admin" }
    }
  }
```

### 2. AI 生成动态脚本

描述你想要的随机数据特征，AI 写出对应的 Python Faker 脚本：

```
输入：返回 10 条随机订单数据，金额在 10-1000 之间，时间在最近 30 天
AI 输出：对应的动态响应脚本（省略）
```

### 3. 从 Mock 反向生成用例

Mock 规则配好后，点击「从 Mock 生成用例」可以反向创建一条测试用例：以这个 Mock 接口为目标，验证它返回的内容是否符合预期。这在「先定接口契约、后写实现」的工作流里很有用。

## 在执行时启用 Mock

配置好的 Mock 规则默认不会自动生效。在 [执行测试](./execution.md) 页面，勾选「启用 Mock 数据」选项后，本批次执行的所有请求会优先匹配 Mock 规则：

- 用例请求 URL 命中某条 Mock 规则 → 返回 Mock 数据
- 用例请求 URL 未命中 → 按正常逻辑请求真实接口

这个机制让你可以**部分 Mock**：核心被测接口走真实，依赖的第三方接口走 Mock，互不干扰。

## 配置示例

### 示例 1：模拟登录失败（密码错误）

| 字段 | 值 |
|------|-----|
| 匹配 URL | `/api/user/login` |
| 请求方法 | `POST` |
| 响应状态码 | `200` |
| 响应体 | `{"code": 1001, "msg": "password incorrect"}` |

### 示例 2：模拟服务端 500

| 字段 | 值 |
|------|-----|
| 匹配 URL | `/api/order/create` |
| 请求方法 | `POST` |
| 响应状态码 | `500` |
| 响应体 | `{"code": 500, "msg": "internal server error"}` |
| 响应延迟 | `3000`（模拟超时） |

### 示例 3：随机用户列表（动态）

开启「动态响应」，脚本返回 5 条随机用户数据，前端列表分页联调用。

## 常见问题

### Mock 没有生效

排查顺序：

1. 确认规则处于「启用」状态
2. 确认执行时勾选了「启用 Mock 数据」（默认不启用）
3. 确认 URL 与方法完全匹配（区分大小写，注意尾斜杠）
4. 用「测试 Mock」按钮验证规则本身

### 动态脚本报错

动态响应脚本报错时，平台会返回错误信息代替响应体。检查脚本语法与导入：Faker 已内置，其他第三方库需平台预装。

### Mock 数据与真实接口结构不一致

Mock 数据结构与真实接口不一致是前后端联调最大的坑。建议从 [Swagger 解析](./swagger.md) 的响应定义直接生成 Mock，保证字段一致。
