# 接口测试平台总览

接口测试平台是五号智能云测试平台的核心部分，覆盖了从接口文档导入、用例管理、参数配置、Mock 服务到执行与报告的完整链路。本页是整个接口测试章节的地图：先看清全貌，再按需深入各功能页。

![仪表盘](/screenshots/zh/dashboard.png)

## 功能全景

平台侧边栏按 7 个分组组织所有功能模块：

| 分组 | 功能模块 | 说明 |
|------|---------|------|
| 概览 | 仪表盘 | 系统数据总览与快速入口 |
| 数据准备 | Swagger 解析、JMeter 解析 | 把外部接口定义和脚本导入平台 |
| Mock 服务 | Mock 管理 | 在真实接口未就绪时返回预定义数据 |
| 测试管理 | 接口参数总览、全局参数、局部参数、测试用例 | 日常使用的核心管理区域 |
| 执行与结果 | 执行测试、测试套件、测试报告 | 跑测试、看结果 |
| AI 功能 | 任务中心、CI/CD 定时任务、CLI 命令行、流程编排、数据工厂、CI 回归测试集、AI 自动测试 | AI 驱动的自动化能力 |
| 系统管理 | 操作日志 | 审计追踪 |

其中AI 功能、系统管理相关功能在 [高级功能](../advanced/data-factory.md) 与 [平台集成](../integration/ci-cd.md) 章节展开，本章聚焦数据准备、Mock、测试管理、执行与结果这四组。

## 模块间的关系

理解模块之间的关系，是高效使用平台的关键。下面这张数据流向图展示了从「数据准备」到「执行报告」的完整链路：

```text
┌─────────────┐   ┌─────────────┐
│ Swagger 解析 │   │ JMeter 解析  │   ← 数据准备：把外部接口定义引入平台
└──────┬──────┘   └──────┬──────┘
       │                 │
       └────────┬────────┘
                ▼
       ┌────────────────┐
       │   测试用例库    │   ← 测试管理：参数、断言、依赖
       └────┬───────┬───┘
            │       │
            ▼       ▼
   ┌────────────┐  ┌────────────┐
   │  全局参数   │  │  Mock 服务  │  ← 支撑层：参数注入、数据替身
   └─────┬──────┘  └─────┬──────┘
         │               │
         └───────┬───────┘
                 ▼
        ┌─────────────────┐
        │    执行测试      │   ← 执行：串行/并行、依赖链、变量传递
        └────────┬────────┘
                 ▼
        ┌─────────────────┐
        │    测试报告      │   ← 结果：HTML / Markdown / Excel
        └─────────────────┘
```

### 三个阶段

- **数据准备阶段**：Swagger / JMeter 解析把接口定义引入平台，沉淀为测试用例
- **测试管理阶段**：在测试用例页配置参数、断言、变量提取；在全局参数与 Mock 服务页配置支撑数据
- **执行与结果阶段**：执行测试跑用例，测试报告查看结果

## 典型工作流

### 工作流 A：新接口快速验证（最短路径）

适合开发同学自测或测试同学对新接口做冒烟。

1. [Swagger 解析](./swagger.md) 导入接口定义 → 自动生成用例
2. [全局参数](./global-params.md) 配置 Token 等公共参数
3. [执行测试](./execution.md) 选模块跑一遍
4. [测试报告](./reports.md) 看通过率，定位失败用例

### 工作流 B：回归测试套件 + CI 定时（团队级）

适合测试主管建立长期回归机制。

1. 把核心用例组织成 [测试套件](./test-suites.md)
2. 在 CI/CD 定时任务中引用套件，配置 Cron 与通知方式
3. 每天定时执行，失败自动邮件 / 企业微信告警

### 工作流 C：复杂业务流程（AI 编排）

适合验证跨多个接口的业务流程，如电商下单全链路。

1. 在 [测试用例](./test-cases.md) 页配置每个接口的变量提取
2. 用 [流程编排](../advanced/flow-orchestration.md) 让 AI 自动推断执行顺序
3. 确认编排结果后执行，验证完整业务链路

### 工作流 D：前后端并行开发（Mock 联调）

适合前端在后端接口未完成时先行开发。

1. 在 [Mock 服务](./mock.md) 配置接口的 Mock 规则
2. 前端请求指向平台 Mock 地址
3. 后端接口就绪后，切换到真实接口执行
