# 空间管理

空间（Workspace）是五号智能云测试平台的多租户隔离单元。每个空间拥有独立的测试用例、测试套件、Mock 服务、执行记录等全部业务数据，空间之间数据完全隔离。

## 谁能使用

空间管理是**超级管理员**专属功能（角色 `super_admin`）。普通用户登录后在顶部空间切换器中选择已有空间，无法创建或管理空间。

## 空间隔离机制

平台采用 **ORM 事件钩子**实现全局自动隔离，而非逐表手动过滤：

- **查询自动过滤**：所有带 `space_id` 列的模型，SELECT 时自动注入 `WHERE space_id = 当前空间`
- **创建自动盖戳**：新建对象时自动填入当前空间的 `space_id`
- **SpaceMember 豁免**：成员表跨空间查询，不受自动过滤影响

这意味着只要业务表有 `space_id` 列且 ORM 模型声明了该属性，就自动享受空间隔离，无需逐个接口改造。

## 空间管理页面

进入 **门户首页 → 空间管理** 卡片（仅超管可见），打开空间管理页面。

![空间管理页面（超管）](/screenshots/zh/space_admin.png)

### 创建空间

1. 点击「+ 创建空间」按钮
2. 填写空间名称和描述
3. 点击确认，新空间创建完成

### 成员管理

每个空间可以管理自己的成员列表：

| 角色 | 权限 |
|------|------|
| **owner** | 空间所有者，可以增删成员、修改角色、删除空间 |
| **admin** | 空间管理员，可管理成员与角色，拥有空间内全部业务操作权限 |
| **editor** | 可以创建、编辑、删除空间内的测试资产 |
| **viewer** | 只读权限，可以查看空间内的所有数据但不能修改 |

![成员管理与角色分配](/screenshots/zh/space_members.png)

### 操作

- **添加成员**：搜索用户 → 选择角色 → 确认添加
- **修改角色**：在成员列表中切换角色下拉框
- **移除成员**：点击成员行的「移除」按钮

## 空间切换器

所有用户登录后，页面顶部右侧会显示**空间切换器**。点击可展开下拉列表，选择要进入的空间。切换空间后页面自动刷新，所有数据切换到目标空间。首次登录尚未选择空间时，会自动弹出同样的选择浮层（空间门禁）。

![空间切换器](/screenshots/zh/space_switcher.png)

- 普通用户：只能切换自己所属的空间
- 超级管理员：可以切换到任意空间

## 技术实现要点

| 组件 | 文件 | 职责 |
|------|------|------|
| 中间件 | `middleware/auth_middleware.py` | 解析 `X-Space-Id` 请求头，设置 contextvar |
| 自动过滤 | `space_filter.py` | SQLAlchemy `do_orm_execute` + `before_flush` 事件钩子 |
| 空间 CRUD | `routers/spaces.py` | 创建/列出/详情/成员管理 API |
| 前端切换器 | `js/space_context.js` | 空间切换 UI + `space-changed` 事件 |
| HTTP 客户端 | `js/http_client.js` | 每个请求自动携带 `X-Space-Id` 头 |
| 迁移脚本 | `migrate_add_space_id_all.py` | 一次性给所有业务表批量补 `space_id` 列 |

## 请求头约定

前端每个 API 请求都会自动携带 `X-Space-Id` 请求头，值为当前空间的 UUID。后端中间件解析该头部并设置 contextvar，ORM 事件钩子读取 contextvar 实现自动过滤。

```
X-Space-Id: <space-uuid>
```

如果用户不是该空间的成员，中间件会自动回退到默认空间，确保不会因空间切换错误导致数据泄漏。
