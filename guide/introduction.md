# 平台介绍

五号智能云测试平台（WuHao AI Cloud Testing Platform）是一个面向接口与 UI 的**一站式自动化测试平台**。它把传统接口测试里散落在 Postman 集合、JMeter 脚本、代码仓库里的测试资产，收敛到一个可视化界面中：导入 Swagger 文档即可生成用例、拖拽即可编排依赖、点击即可执行、跑完自动出报告。

平台的核心设计目标是**降低自动化测试的落地门槛**。测试工程师不需要写 Python/Java 代码，开发工程师不需要维护脚本仓库，测试主管能够拿到统一的执行记录与质量数据。与此同时，平台把 AI 能力深度融进测试生命周期的每个环节：AI 推断用例依赖、AI 生成异常场景、AI 生成测试参数、AI 自动编排流程。

打开平台地址，未登录会自动跳转到登录页；首次使用可在登录页注册账号。登录支持中英双语切换与深色模式。

登录后首先进入[门户首页](./portal.md)，通过卡片导航至各功能模块：产品文档、AI 配置、AI 用例生成、接口自动化、UI 自动化（超级管理员额外可见监控中心和空间管理）。

## 平台能做什么

平台的接口测试部分覆盖了测试生命周期的完整链路，按侧边栏的 7 个功能分组组织：

- **概览**：仪表盘，全局统计与快速入口
- **数据准备**：Swagger 解析、JMeter 解析，把外部接口定义和脚本导入平台
- **Mock 服务**：在真实接口未就绪时返回预定义数据，支持前后端并行开发
- **测试管理**：接口参数总览、全局参数、局部参数、测试用例，是日常使用的核心区域
- **执行与结果**：执行测试、测试套件、测试报告
- **AI 功能**：任务中心、CI/CD 定时任务、CLI 命令行、流程编排、数据工厂、CI 回归测试集、AI 自动测试
- **系统管理**：操作日志，完整审计追踪

接口测试之外，平台还提供独立的 UI 自动化测试能力（流程编排、元素库、执行记录），本文档站的 [UI 测试][1] 章节另行介绍。

## 核心差异化优势

以下四项能力是市面同类工具做不到或做不好的，也是本平台的核心竞争壁垒。

### 1. AI 自动探索网页，一键生成测试

::: tip 竞品做不到
Apifox、Postman、Selenium 都没有「AI 探索」能力——它们最多帮你「录制」已知操作，需要你手动一步步点。本平台的 AI 能「发现」你没想过的测试场景。
:::

给一个 URL，AI 自动完成全流程：

- **打开页面**：无头浏览器打开目标页面（支持自动登录）
- **分析元素**：抓取所有可交互元素，按可测性分类（表单/按钮/表格/搜索/导航）
- **规划场景**：AI 根据元素分布，自动规划「值得测」的场景清单
- **生成步骤**：每个场景生成一整套步骤（含等待、断言）
- **防编造校验**：每个 locator 与真实抓取的元素比对，剔除 AI 编造的步骤
- **直接落库**：生成的流程保存为草稿，人工复核后即可执行

详见 [AI 网站探索](../ai/ui-exploration.md)。

### 2. 接口测试 + UI 测试一体化

::: tip 竞品做不到
Postman 只做接口、Selenium 只做 UI。团队要维护两套工具、两套用例、两套 CI，接口测试团队和 UI 测试团队各搞各的，端到端流程验证无人覆盖。
:::

本平台把接口和 UI 测试融为一体：

- **统一项目结构**：接口和 UI 测试共用同一套项目/模块/元素库
- **混合回归测试集**：CI 回归集里可以编排「先调接口下单，再用 UI 验证订单页渲染」
- **一个流水线跑完**：一套 CI 配置，接口 + UI 一起跑，一份报告看全局
- **变量跨域共享**：接口提取的 token 可以传给 UI 流程用，反之亦然

### 3. AI 融入测试全流程（不只是聊天）

::: tip 竞品做不到
很多平台标榜「AI 辅助」只是在文本框里接了个 GPT，你问它答。本平台的 AI 是主动的、贯穿流程的。
:::

| AI 能力 | 别人的做法 | 本平台的做法 |
|--------|-----------|-------------|
| **用例依赖** | 手动排执行顺序 | AI 分析接口参数，自动推断调用链和执行顺序 |
| **异常用例** | 手动逐个写边界值 | AI 从正常用例自动生成必填缺失/格式错误/SQL 注入等异常集 |
| **流程编排** | 手动拖拽连线 | AI 分析接口返回，推断前置后置关系，一键生成编排图 |
| **测试数据** | 手动编或写脚本 | 数据工厂按规则批量生成，AI 推断字段类型填充合理值 |

### 4. 数据工厂 + 变量提取 + 依赖编排

::: tip 竞品做不到
传统测试工具里，造测试数据是最耗时的体力活。Postman 要写 Pre-request Script，Selenium 要写 Python 脚本。本平台全零代码。
:::

| 能力 | 传统做法 | 本平台 |
|------|---------|--------|
| **测试数据生成** | 手动编手机号/邮箱/身份证，或写 Python 脚本 | 树形数据工厂，内置随机规则 + 自定义规则，一键引用 |
| **变量提取** | Postman 写 `pm.environment.set()` 脚本 | 零代码配置提取规则，A 接口的返回值 B 接口直接 `${变量名}` 引用 |
| **依赖编排** | 手动排顺序、手动传 token | AI 推断依赖，前置后置用例自动串联，变量自动流转 |

## 与同类工具对比

平台并不是要取代 Postman 或 JMeter，而是把它们的单点能力整合进一个面向团队的协作平台。下表帮助你在不同场景下选择合适的工具：

| 能力 | Postman | JMeter | Selenium | **本平台** |
|---|---|---|---|---|
| 接口功能测试 | ✅ | ✅ | ❌ | ✅ |
| UI 自动化 | ❌ | ❌ | ✅ | ✅ |
| 零代码可视化 | 部分 | ❌ | ❌ | ✅ |
| Swagger 文档驱动 | ✅ | ❌ | ❌ | ✅ |
| Mock 服务 | ✅ | ❌ | ❌ | ✅ |
| AI 辅助生成 | ❌ | ❌ | ❌ | ✅ |
| 用例依赖编排 | 手动 | 手动 | 手动 | ✅ AI 推断 |
| 定时 / CI 集成 | 部分 | ✅ | 部分 | ✅ |
| 测试数据工厂 | ❌ | ❌ | ❌ | ✅ |
| 性能压测 | ❌ | ✅ | ❌ | ❌ |
| 学习成本 | 低 | 高 | 中 | 低 |

::: tip 什么时候还应该用 Postman / JMeter
- 需要做**高并发性能压测**时，JMeter 仍是更专业的选择，平台支持导入 `.jmx` 脚本但不替代压测。
- 开发同学在本地**快速调试单个接口**时，Postman 的轻量体验依然顺手，可以把验证好的请求再沉淀到平台。
:::

## 适用场景

### 适合的平台场景

- **新接口上线自测**：开发提交 Swagger 文档 → 平台一键生成用例 → 配置 Token → 执行验证
- **每日回归测试**：把核心接口组织成测试套件 → 配置 CI/CD 定时任务 → 每天凌晨自动跑并发邮件通知
- **前后端并行开发**：后端接口未就绪时，用 Mock 服务返回模拟数据，前端不被阻塞
- **复杂业务流程测试**：登录 → 查询 → 下单 → 支付 → 删除，让 AI 自动推断依赖顺序并提取变量
- **异常与边界测试**：选一条正常用例，AI 自动生成必填缺失、格式错误、SQL 注入等异常场景

### 不适合的场景

- **大规模性能压测**：平台专注于功能正确性验证，不是压力测试工具
- **GUI 界面元素测试**：这部分由平台的 [UI 测试][2] 模块覆盖，本接口测试平台不处理页面渲染
- **数据库直连测试**：平台面向 HTTP / WebSocket 接口，不做 SQL 直查

## 技术架构速览

| 层 | 技术选型 |
|----|---------|
| 后端框架 | FastAPI (Python) |
| 数据库 | MySQL 8 + SQLAlchemy ORM |
| 测试引擎 | 自研 HTTP / WebSocket 请求引擎 |
| AI 集成 | LiteLLM 统一接入，默认 Ollama `qwen3:14b` |
| 数据生成 | Faker |
| 前端 | 原生 HTML + JavaScript 单页应用，企业级紫色主题 |
| 部署 | Docker Compose 一键启动，或 `python run.py` 直跑 |
